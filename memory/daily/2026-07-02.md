## 下午 - Per-task notification route ✅

**问题**：notification 投递依赖全局 lastMainChannelTarget
1. channel/target 不匹配（target 是飞书，channel 写死 discord）
2. 多平台覆盖（飞书聊完切 Discord，lastMain 被覆盖）
3. 客户群风险（客户群消息更新 lastMain → notification 发到客户群）

**方案**：每个 notification 自带 route（channel + target），不依赖全局状态

| 路径 | route 来源 | 存储 | 原因 |
|------|-----------|------|------|
| bash bg task | ctx | 内存 TaskState | task 跟进程同生命周期 |
| calendar task | ctx | DB events 表 | reminder 可能几天后触发 |

**改动**：
- calendar/db.ts: 加 created_channel + created_channel_target 列
- calendar/commands.ts: addTask 存 route
- calendar/reminder-plugin.ts: 从 DB 读 per-task route，逐条投递；无 route 跳过
- tools/task-manager.ts: kill 补 route
- tools/calendar.ts: add-task 传 ctx route
- engine-startup.ts: 删 lastMain 整套（callback 无 route 不投递）

**验证**（三条路径全到飞书）：
- task-created notification ✅
- reminder notification ✅
- bash background task ✅

**文档**：engine/docs/notification-route-per-task.md + docs/decisions/
