# RTX 3090 部署 Qwen3.6-27B 完整教程（小红书参考）

> 来源：小红书用户的踩坑实录。翀哥存起来参考本地模型部署。
> 七张图原图保存在 `/Users/chongzhang/xiaoke//media/from-chongge/2026-07-21-小书Qwen27B教程图*.jpeg`

## 1. 环境与需求

**硬件配置：**
- GPU：NVIDIA GeForce RTX 3090 24GB
- 驱动：555.xx 以上，CUDA 12+
- 系统：Ubuntu 22.04 / 24.04

**为什么换 27B？**
- 之前用的是 Qwen3.6-35B（MoE 架构），显存占 ~20GB
- 加 256K 上下文后接近 24GB 极限，没法做视频分析了

**参数对比：**
| 指标 | 35B (MoE) | 27B (Q4_K_M) |
|------|-----------|--------------|
| 量化方式 | IQ4_XS | Q4_K_M |
| 模型权重显存 | ~20 GB | ~16.8 GB |
| 256K KV Cache | 爆显存 | ~4.2 GB |
| 多模态支持 | 不支持 | 原生支持 |
| 总显存 | ~24 GB 极限 | ~22 GB 有余量 |

## 2. 下载模型

**1. 下载主模型 GGUF：**
```bash
huggingface-cli download unsloth/Qwen3.6-27B-GGUF \
  Qwen3.6-27B-Q4_K_M.gguf \
  --local-dir ~/models/qwen36-27b/
```
注意：路径别带冒号，如果文件夹名字有冒号记得重命名
```bash
mv ~/models/qwen36/qwen36:27b ~/models/qwen36/qwen36-27b
```

**2. 下载多模态投影文件 mmproj：**
```bash
huggingface-cli download Qwen/Qwen3.6-27B-GGUF \
  mmproj-BF16.gguf \
  --local-dir ~/models/qwen36-27b/
```
注意：Unsloth 仓库通常不含 mmproj，要去 Qwen 官方 GGUF 仓库拿！

## 3. 手动测试启动

**最终优化后的启动命令：**
```bash
~/llama.cpp/build/bin/llama-server \
  -m ~/models/qwen36-27b/Qwen3.6-27B-Q4_K_M.gguf \
  --mmproj ~/models/qwen36-27b/mmproj-BF16.gguf \
  --port 8080 --host 0.0.0.0 \
  -c 262144 --flash-attn on \
  --cache-type-k q4_0 --cache-type-v q4_0 \
  -ngl 99 --temp 0.6 --top-p 0.95 --jinja
```

**参数解读：**
- `-c 262144`：256K 上下文长度
- `--cache-type-k/v q4_0`：4-bit KV Cache 量化，大幅降低显存
- `-ngl 99`：全部层 offload 到 GPU
- `--flash-attn on`：Flash Attention 加速
- `--temp 0.6 --top-p 0.95`：生成参数
- `--jinja`：启用 Jinja 模板（Qwen 需要）

**成功标志：** nvidia-smi 显示显存约 23.7 GB，日志中出现 `ggml_cuda_init: found 1 CUDA devices`

**快速验证命令：**
```bash
# 检查服务是否正常
curl http://localhost:8080/v1/models

# 测试对话
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"你的模型名","messages":[{"role":"user","content":"你好"}]}'
```

## 4. systemd 服务固化（开机自启）

**1. 停用旧服务并备份：**
```bash
sudo systemctl stop llama-server
sudo systemctl disable llama-server
sudo cp /etc/systemd/system/llama-server.service \
  /etc/systemd/system/llama-server.service.bak
```

**2. 编辑服务文件** `/etc/systemd/system/llama-server.service`：

```ini
[Unit]
Description=llama.cpp server for Qwen3.6-27B
After=network.target multi-user.target
Wants=nvidia-persistenced.service

[Service]
Type=simple
User=#你的用户名
WorkingDirectory=#你的路径/llama.cpp

Environment="LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu"
Environment="CUDA_VISIBLE_DEVICES=0"

ExecStartPre=/bin/sleep 2

ExecStart=#你的路径/llama.cpp/build/bin/llama-server \
  -m #模型路径/Qwen3.6-27B-Q4_K_M.gguf \
  --mmproj #模型路径/mmproj-BF16.gguf \
  --mmproj-offload --port 8080 --host 0.0.0.0 \
  -c 262144 --flash-attn on \
  --cache-type-k q4_0 --cache-type-v q4_0 \
  -ngl 99 --temp 0.6 --top-p 0.95 --jinja

Restart=always
RestartSec=15

[Install]
WantedBy=multi-user.target
```

**踩坑提醒：**
- LD_LIBRARY_PATH 必须指向 libcuda.so 实际路径
- ExecStartPre=/bin/sleep 2 避免 GPU 驱动未就绪
- Wants=nvidia-persistenced 保持 GPU 状态稳定

**3. 启用并启动：**
```bash
sudo systemctl enable nvidia-persistenced
```

## 5. GPU 开机自启稳定性问题（重点！）

**问题现象：**
改好 systemd 并设了开机自启，但有时候重启后发现 llama-server 进程虽然在，nvidia-smi 显存为 0——模型根本没加载到 GPU！日志里也没有 `ggml_cuda_init`。手动重启服务却能正常加载。

**原因分析：**
- **竞争条件**：系统启动时 GPU 驱动初始化需要时间，systemd 可能在驱动就绪前就启动了服务，导致 fallback 到 CPU 模式
- **环境变量传递**：LD_LIBRARY_PATH 在 systemd 环境中可能被重置
- **NVIDIA 驱动服务**：未启用 nvidia-persistenced 可能导致 GPU 状态不稳定

**终极解决方案（5 条一起做）：**
1. **添加启动延迟**：`ExecStartPre=/bin/sleep 2` 等待 GPU 驱动完全就绪
2. **增加服务依赖**：`Wants=nvidia-persistenced.service` 确保持久化服务已运行
3. **显式设置环境变量**：LD_LIBRARY_PATH + CUDA_VISIBLE_DEVICES=0
4. **启用 nvidia-persistenced**：`sudo systemctl enable nvidia-persistenced`
5. **确认 libcuda.so 路径**：`find /usr -name "libcuda.so"` 找到实际路径

**稳定性验证步骤：**
```bash
# 1. 重启服务器
sudo reboot

# 2. 等 1 分钟后检查
nvidia-smi  # 应该看到 ~23.7 GB 显存占用

# 3. 查看日志确认
sudo journalctl -u llama-server -n 50 | grep -E "CUDA|cuda"

# 4. 建议连续重启 3 次验证稳定性
```

## 6. 性能评估

**实测数据：**
- 上下文长度：262144 tokens (256K)
- 模型权重占显存：~16.8 GB
- KV Cache (q4_0)：~4.2 GB
- mmproj + 开销：~0.9 GB
- 总显存占用：~23.7 GB
- prompt 处理速度：600-1200 tokens/s
- 生成速度：25-33 tokens/s

**多模态性能：**
- 图像编码 + 解码总耗时：约 0.7 秒（小图）~ 6 秒（4K 大图）
- 视觉投影已成功 offload 到 GPU，推理部分充分利用 GPU 加速

💡 图片处理慢？在客户端提前缩放到 640x640 以内，可大幅缩短预处理时间。

## 7. 常见问题（FAQ）

**Q1：服务启动后显存为 0（GPU 未加载）**
确认 LD_LIBRARY_PATH 指向 libcuda.so 实际目录，添加 ExecStartPre=/bin/sleep 2，启用 nvidia-persistenced。

**Q2：图像处理速度慢（>4 秒）**
发送的图片尺寸过大。在客户端提前缩放到 640x640 以内。

**Q3：端口占用**
```bash
sudo systemctl stop llama-server; sudo pkill -9 llama-server
```

**Q4：修改参数后服务未生效**
修改服务文件后必须执行：
```bash
sudo systemctl daemon-reload
sudo systemctl restart llama-server
```

## 8. 总结与心得

1. **量化选择**：24GB 显存，27B + Q4_K_M + q4.0 KV Cache 是 256K 上下文下最平衡的方案
2. **多模态支持**：mmproj 必须与主模型版本匹配，建议强制 `--mmproj-offload`
3. **systemd 环境变量**：LD_LIBRARY_PATH 和 CUDA_VISIBLE_DEVICES 缺一不可，加启动延迟避免竞争
4. **稳定性优化**：nvidia-persistenced + 服务依赖，彻底解决开机 GPU 加载不稳定
5. **监控与日志**：journalctl -u llama-server -f 实时查看，curl 快速验证 API，定期检查 nvidia-smi

🔥 这套配置已稳定运行数周，用于视频分析、长文档摘要等任务，效果很好！
