# Hermes 元数据注入调研

## 调研时间：2026-06-18 01:30

## 结论：Hermes 不在每条消息上加时间戳

### Hermes 的元数据注入分两层

#### 第一层：System Prompt（每轮重建，frozen at build time）

位置：`run_agent.py` line 5251-5256

```python
now = _hermes_now()
timestamp_line = f"Conversation started: {now.strftime('%A, %B %d, %Y %I:%M %p')}"
```

- **只注入一次**——"Conversation started" 时间，不是每条消息的时间
- 格式：`Conversation started: Thursday, June 18, 2026 01:30 AM`
- 还带 Session ID 和 Model 信息
- 这相当于我们的"运行时上下文"

#### 第二层：Session Context Prompt（system prompt 的一部分）

位置：`gateway/session.py` `build_session_context_prompt()` line 231-419

注入内容：
- **Source**: 平台名 + 描述（如 `Discord (DM with sleepyzhang)` 或 `Discord (group: 客厅)`）
- **Channel Topic**: 频道主题（如果有）
- **User**: 用户名（单用户session）或 "Multi-user session" 标记
- **Platform notes**: 平台特定提示（Discord ID、Slack限制等）
- **Connected Platforms**: 已连接平台列表
- **Home Channels**: 默认发送目标
- **Delivery options**: 定时任务投递选项

关键：**这些都在 system prompt 里，不在每条消息上**

#### 第三层：多用户session的消息前缀（唯一的per-message注入）

位置：`gateway/run.py` line 5951-5952

```python
if _is_shared_multi_user and source.user_name:
    message_text = f"[{source.user_name}] {message_text}"
```

- **只在多用户共享session时**才加前缀
- 格式极简：`[sleepyzhang] 消息内容`
- **没有时间戳、没有平台名、没有频道ID**
- 单用户session（如DM）连这个前缀都没有

### Hermes vs 我们的对比

| 维度 | Hermes | 我们（Engine） |
|------|--------|---------------|
| 时间戳 | system prompt 里 "Conversation started" 一次 | runtime context 每轮更新当前时间 |
| 平台来源 | system prompt Session Context | runtime context + meta头 |
| 每条消息前缀 | 仅多用户session加 `[用户名]` | 每条都加 `[meta: HH:MM/平台#频道@人]` |
| 频道ID | system prompt 里 Discord IDs 块 | meta头 `#频道ID` |
| 用户名 | system prompt 或 `[用户名]` 前缀 | meta头 `(fromName)` |

### 关键发现

1. **Hermes 不在每条消息上加时间戳**——只在 system prompt 里放一个 "Conversation started" 时间
2. **Hermes 的 per-message 前缀只在多用户session才启用**，格式极简 `[用户名]`
3. **Hermes 把大部分元数据放在 system prompt 的 Session Context 里**，不是每条消息
4. **我们的 meta 头比 Hermes 更激进**——每条消息都带完整元数据+时间戳

### 翀哥说的"OpenClaw是有时间的"

OpenClaw（CC那边）的消息格式确实带时间戳，但那可能是 CC 自己的格式，不是 Hermes 的。
Hermes 本身不这么做。

### 建议

我们的 meta 头改造走在了 Hermes 前面。时间戳加不加取决于：
- **加**：每条消息自带时间，翻历史一目了然，但多耗token
- **不加**：靠 system prompt 的当前时间，跟 Hermes 一样，省token

翀哥之前说"openclaw是有时间的"，如果指的是 CC 的消息格式，那不是 Hermes 的做法。
