## 一、完整架构：OAC 用了几个 LLM？

**Agent 模式最多 3 个 LLM（经典模式只有 1 个，无视觉能力）：**

| # | LLM 角色 | 模型 | 用途 | 独立client |
|---|---------|------|------|-----------|
| ① | 视觉 VLM | qwen3-vl-flash | 把摄像头帧翻译成结构化文字描述 | ✅ |
| ② | 对话主 LLM | qwen3.6-plus | 生成回复，支持工具调用 | ✅ |
| ③ | 语义打断检测 | qwen-plus / Qwen3-8B | 判断用户是否打断、是否说完了 | ✅ |

**经典模式**（大部分配置）：只有 ②，没有视觉感知链路。

## 二、完整数据流（Agent 模式）

```
┌─ 上行：摄像头 ──────────────────────────────────────────┐
│                                                         │
│  浏览器 getUserMedia(video)                              │
│    → WebRTC track (H.264)                               │
│    → fastrtc video_receive(frame)  # numpy RGB          │
│    → put_data(CAMERA_VIDEO)                             │
│    → StreamManager 分发                                 │
│    → PerceptionHandler                                  │
│        ├─ 帧缓冲：30fps→每10帧取1帧(3fps)→缓冲最多30帧   │
│        ├─ 每3秒触发摘要                                  │
│        ├─ 从缓冲均匀采样4帧                              │
│        └─ OpenAIVisionModel.generate_perception()       │
│              → base64编码 → qwen-vl API (type="video")  │
│              → XML解析 → PerceptionData                 │
│              → submit_data(PERCEPTION_CONTEXT)          │
│                                                         │
├─ 上行：语音 ────────────────────────────────────────────┐
│                                                         │
│  浏览器 getUserMedia(audio)                              │
│    → WebRTC → fastrtc → SileroVAD                       │
│    → SenseVoice ASR → HUMAN_TEXT                        │
│    → SemanticTurnDetector（判断是否说完了）               │
│                                                         │
├─ 中枢：ChatAgentHandler ────────────────────────────────┤
│                                                         │
│  收到 HUMAN_TEXT 时：                                    │
│    1. 取缓存的 PERCEPTION_CONTEXT（视觉描述）             │
│    2. 构建4层Prompt：                                    │
│       L1: Stable Core (输出约束)                        │
│       L2: Persona Snapshot (人格)                       │
│       L3: Environment State ← ★视觉描述注入这里          │
│       L4: Recent Dialogue (对话历史+当前消息)            │
│    3. 调对话LLM(qwen3.6-plus) → 流式回复                │
│                                                         │
│  收到 ENVIRONMENT_EVENT 时（挥手/展示物品）：             │
│    → 可以不等用户说话，主动触发对话                       │
│                                                         │
├─ 下行：回复 ────────────────────────────────────────────┤
│                                                         │
│  AVATAR_TEXT (流式)                                      │
│    → CosyVoice TTS → AVATAR_AUDIO                       │
│    → FlashHead → AVATAR_VIDEO                           │
│    → WebRTC 推流给浏览器                                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 三、摄像头视频传输详解

### 3.1 浏览器端

OAC 用 fastrtc 的 `Stream(modality="audio-video", mode="send-receive")`。

**track_constraints**（client_handler_rtc.py L421-429）：
```python
"audio": {
    "sampleRate": 16000,
    "channelCount": 1,
    "autoGainControl": False,
    "noiseSuppression": False,
    "echoCancellation": True,
}
```
视频没有特殊 constraints，用默认。

### 3.2 服务端接收

fastrtc 收到帧后调用 `RtcStream.video_receive(frame)`（rtc_stream.py L237-248）：

```python
async def video_receive(self, frame):
    timestamp = self.client_session_delegate.get_timestamp()
    if timestamp[0] / timestamp[1] < self.stream_start_delay:  # 0.5s
        return  # 前0.5秒的帧丢弃
    self.client_session_delegate.put_data(
        EngineChannelType.VIDEO,
        frame,         # numpy ndarray (H, W, 3) RGB
        timestamp,
        self.fps,      # 30fps
    )
```

**帧格式**：numpy ndarray, shape=(H, W, 3), RGB

### 3.3 帧处理策略（PerceptionHandler）

**关键帧选择**（_add_to_buffer L327-343）：
```python
# 每 key_frame_interval=10 帧保存 1 帧
if context.frame_count % 10 == 0:
    context.frame_buffer.append(frame)
# 缓冲上限 max_buffer_frames=30
```
→ 30fps 输入 ÷ 10 = **3fps 存缓冲**

**定时摘要**：
```python
# 每 summary_interval=3.0 秒触发
if current_time - last_summary_time >= 3.0:
    self._generate_and_emit_perception(context, output_definitions)
```

### 3.4 VLM 调用（OpenAIVisionModel）

**帧选择**（_select_frames）：
```python
max_frames = 4
# 均匀采样：从头到尾等间距取4帧
step = max(1, len(frames) // max_frames)
selected = frames[::step][:max_frames]
```

**最少4帧**（MIN_VIDEO_FRAMES=4），不足重复补足（阿里云 qwen-vl 要求）

**消息构建**（_build_messages）：
```python
# 帧转 base64 data URL
content = [
    {"type": "video", "video": video_frames},  # base64 图片列表
    {"type": "text", "text": "请根据这段实时摄像头视频..."}
]
```
**发的是 image base64 列表，API 标为 `"type": "video"`，不是视频文件**

**API 调用**：
```python
response = client.chat.completions.create(
    model="qwen-plus-vl",
    messages=messages,
    stream=False,
    max_tokens=600,
    timeout=6.0,
)
```

### 3.5 VLM System Prompt

完整 system prompt（vision_model_interface.py L342-381）：

```
你是一个具身智能体的视觉感知系统。你正在通过摄像头实时观察用户。

重要视角说明：
- 你的视角是摄像头视角，用户正面对着你
- 你收到的是一段实时视频流的关键帧序列
- 当你看到一个人举着手机对着画面时，这表示用户正在向你展示手机

请以第一人称视角描述你观察到的内容，严格使用以下 XML 标签格式输出：

<scene_summary>一句话描述（"我看到用户..."）</scene_summary>
<location>场景位置</location>
<people>可见的人物</people>
<objects>可见的物品</objects>
<activities>正在进行的活动</activities>
<emotion>用户情绪（focused/happy/confused/sad/angry/surprised/neutral）</emotion>
<gaze>用户视线方向</gaze>
<posture>用户姿态（sitting/standing/leaning/lying）</posture>
<action>用户当前动作（speaking/typing/holding_phone/gesturing/idle/reading）</action>
<events>交互事件（可为空）</events>
```

**交互事件**（confidence≥0.7才触发，5秒去重）：
- waving（挥手）
- showing_object（展示物品）
- asking_for_attention（求关注）
- leaving（离开）
- arriving（到达）

### 3.6 异步管理器（AsyncPerceptionManager）

**最新优先策略**：
- 线程池（max_workers=3）
- 更新的轮次已发送则旧轮次丢弃
- 达到并发上限跳过本轮，保留帧缓冲

### 3.7 XML 响应解析

```python
PerceptionData:
  scene_summary: str          # "我看到用户正在..."
  scene_structure:
    location / people / objects / activities
  user_state:
    emotion / gaze / posture / action
  detected_events: List[dict] # [{event_type, confidence, description}]
```

## 四、视觉描述如何用进对话

### 4.1 PERCEPTION_CONTEXT → 缓存（不立即调 LLM）


### 4.2 用户说话时注入 Prompt（L3 Environment State）

```python

    env_state = context.cached_perception.scene_summary
```

## 五、语义打断检测（SemanticTurnDetector）

**这是我们之前做的打断机制的 OAC 版本——用 LLM 判断而不是纯 VAD。**

### 5.1 两种模式

| 模式 | duplex_mode | 输入 | 功能 |
|------|-------------|------|------|
| 双工 | True | HUMAN_DUPLEX_TEXT | 实时检测打断 + 判断说完没 |
| 非双工 | False | INTERRUPT signal | 对客户端中断信号做语义验证 |

### 5.2 两个核心 Prompt

**打断检测**（avatar 说话时用户说话）：
```
数字人正在播报：{avatar_text}
用户刚才说的：{user_text}
判断标准：
1. 明确要求暂停（等一下/停/暂停）→ 打断
2. 针对播报提出回应/提问/否定 → 打断
3. 开始新话题 → 打断
4. 只是语气词（嗯/哦/好）→ 不打断
只回答"打断"或"不打断"
```

**说完检测**（判断用户是否说完了）：
```
用户目前说的话：{user_text}
- 句子结构完整 → 完成
- 明显不完整（"我想要..."没说完）→ 未完
- 只是语气词 → 未完
只回答"完成"或"未完"
```

### 5.3 打断意图分析（第三层判断）

打断后还要判断意图：
- `pure_interrupt`：只想停止当前播报（"停"/"够了"）
- `has_new_topic`：有新问题/新话题（"我想问..."/"但是..."）

### 5.4 我们的打断 vs OAC 的区别

| | 我们的 voice-chat | OAC |
|---|---|---|
| 触发 | VAD 500ms debounce | 语义 LLM 判断 |
| 判断 | 有声音就打断 | LLM 判断是否真的要打断 |
| 说完检测 | VAD post_end_monitor | 语义 LLM 判断句子完整性 |
| 延迟 | 低（纯音频） | 高（每次调 LLM） |
| 准确度 | 低（语气词也打断） | 高（"嗯"不打断） |

## 六、H.264 编解码

client_handler_rtc.py 前 200 行：
- 硬件编码优先（h264_nvenc / h264_qsv / h264_videotoolbox）
- fallback 到 libx264（ultrafast, baseline, zerolatency）
- bitrate 自适应（0.5-2.5 Mbps，默认1.5 Mbps）
- monkey-patch 替换 aiortc 编码逻辑

## 十、我们怎么移植

### 方案：fastrtc video track + 独立 VLM

**前端 test-page.html**：
- `getUserMedia({audio: true, video: true})`
- 加 video track 到 peer connection（sendonly）

**服务端 server.py**：
- fastrtc handler 加 `video_receive(frame)`
- 仿 PerceptionHandler 做帧缓冲（每10帧取1帧，最多30帧）
- 每 3 秒取 4 帧调 qwen-plus-vl
- 描述结果通过 SSE 广播或写入引擎上下文

**模型选择**：
- VLM: qwen-plus-vl（已有 DashScope Key）
- 不需要额外改对话 LLM，视觉描述注入 system prompt 即可

### 注意事项
- VLM 6秒超时 vs 3秒触发 → 会跳过中间轮次（最新优先策略）
- base64 编码约1.3倍体积，4帧JPEG约200-400KB
- 语义打断检测是可选增强，不影响基本功能
