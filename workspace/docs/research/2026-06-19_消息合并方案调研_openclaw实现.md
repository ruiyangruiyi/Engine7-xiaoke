# 消息合并方案调研（openclaw 实现）

## 调研背景

6/19 翀哥要求调研 openclaw 的消息合并方案，作为 Engine 消息队列合并的参考。

## 调研结论

openclaw 有完整的消息合并实现，核心是 **debounce 模式**：同 channel + 同作者的纯文本消息在时间窗口内合并，带图/附件的消息不参与合并。

## 核心文件

### 1. 通用 debounce 工厂

**文件**：`src/auto-reply/inbound-debounce.ts`（284 行）

**核心函数**：`createInboundDebouncer<T>(params)`

**参数**：
```typescript
{
  debounceMs: number,              // 合并窗口时间（毫秒）
  maxTrackedKeys?: number,         // 最大跟踪 key 数（默认 2048）
  buildKey: (item: T) => string | null | undefined,  // 构造合并 key
  shouldDebounce?: (item: T) => boolean,             // 判断是否参与合并
  resolveDebounceMs?: (item: T) => number | undefined, // 动态调整窗口
  serializeImmediate?: boolean,    // 立即执行时是否串行
  onFlush: (items: T[]) => Promise<void>,  // 合并后回调
  onError?: (err: unknown, items: T[]) => void,
}
```

**返回值**：
```typescript
{
  enqueue: (item: T) => Promise<void>,  // 入队
  flushKey: (key: string) => Promise<void>,  // 强制刷新某 key
  cancelKey: (key: string) => boolean,  // 取消某 key
}
```

**核心机制**：
- **buffer 机制**：同 key 的消息在 `debounceMs` 窗口内累积到 `buffer.items[]`
- **key 链**：`keyChains: Map<string, Promise<void>>` 保证同 key 消息串行执行
- **超时刷新**：`setTimeout` 触发 `onFlush(buffer.items)` 一次性处理
- **立即执行**：不满足 debounce 条件时直接 `onFlush([item])`

**关键代码片段**：
```typescript
// L207-245: enqueue 入口
const enqueue = async (item: T) => {
  const key = params.buildKey(item);
  const debounceMs = resolveDebounceMs(item);
  const canDebounce = debounceMs > 0 && (params.shouldDebounce?.(item) ?? true);

  if (!canDebounce || !key) {
    // 不满足条件，立即执行
    await runFlush([item]);
    return;
  }

  const existing = buffers.get(key);
  if (existing) {
    // 同 key 已有 buffer，追加
    existing.items.push(item);
    existing.debounceMs = debounceMs;
    scheduleFlush(key, existing);  // 重置超时
    return;
  }

  // 新建 buffer
  let buffer!: DebounceBuffer<T>;
  const reservedTask = enqueueReservedKeyTask(key, async () => {
    if (buffer.items.length === 0) return;
    await runFlush(buffer.items);
  });
  buffer = {
    items: [item],
    timeout: null,
    debounceMs,
    releaseReady: reservedTask.release,
    readyReleased: false,
    task: reservedTask.task,
  };
  buffers.set(key, buffer);
  scheduleFlush(key, buffer);  // 启动超时
};

// L190-198: scheduleFlush 超时刷新
const scheduleFlush = (key: string, buffer: DebounceBuffer<T>) => {
  if (buffer.timeout) {
    clearTimeout(buffer.timeout);  // 重置
  }
  buffer.timeout = setTimeout(async () => {
    await flushBuffer(key, buffer);
  }, buffer.debounceMs);
  buffer.timeout.unref?.();  // 不阻塞进程退出
};
```

### 2. Discord 用法

**文件**：`extensions/discord/src/monitor/message-handler.ts:119-242`

**创建 debouncer**：
```typescript
const { debouncer } = createChannelInboundDebouncer<{
  data: DiscordMessageEvent;
  client: Client;
  abortSignal?: AbortSignal;
  replayKey?: string;
}>({
  cfg: params.cfg,
  channel: "discord",
  buildKey: (entry) => {
    const message = entry.data.message;
    const authorId = entry.data.author?.id;
    if (!message || !authorId) return null;
    const channelId = resolveDiscordMessageChannelId({
      message,
      eventChannelId: entry.data.channel_id,
    });
    if (!channelId) return null;
    return `discord:${params.accountId}:${channelId}:${authorId}`;
  },
  shouldDebounce: (entry) => {
    const message = entry.data.message;
    if (!message) return false;
    const baseText = resolveDiscordMessageText(message, { includeForwarded: false });
    return shouldDebounceTextInbound({
      text: baseText,
      cfg: params.cfg,
      hasMedia:
        (message.attachments && message.attachments.length > 0) ||
        hasDiscordMessageStickers(message),
    });
  },
  onFlush: async (entries) => {
    // ... 合并逻辑
  },
});
```

**key 构造**：`discord:{accountId}:{channelId}:{authorId}`
- 同 channel + 同作者 = 合并
- accountId 区分多 bot 场景

**shouldDebounce 判断**：
```typescript
// src/channels/inbound-debounce-policy.ts:11-29
export function shouldDebounceTextInbound(params: {
  text: string | null | undefined;
  cfg: OpenClawConfig;
  hasMedia?: boolean;
  commandOptions?: CommandNormalizeOptions;
  allowDebounce?: boolean;
}): boolean {
  if (params.allowDebounce === false) return false;
  if (params.hasMedia) return false;  // ⭐ 带图/附件不合并
  const text = normalizeOptionalString(params.text) ?? "";
  if (!text) return false;
  return !hasControlCommand(text, params.cfg, params.commandOptions);  // 命令不合并
}
```

**关键规则**：
- **带图/附件 → 不合并**（`hasMedia → false`）
- **命令消息 → 不合并**（`hasControlCommand → false`）
- **纯文本 → 合并**

**onFlush 合并逻辑**：
```typescript
onFlush: async (entries) => {
  const last = entries.at(-1);
  if (!last) return;
  const replayKeys = entries.map((entry) => entry.replayKey).filter(isNonEmptyString);
  const abortSignal = last.abortSignal;
  if (abortSignal?.aborted) {
    releaseDiscordInboundReplay({ replayKeys, error: abortSignal.reason, replayGuard });
    return;
  }
  try {
    if (entries.length === 1) {
      // 单条：正常处理
      const ctx = await preflight({ ...params, data: last.data, client: last.client });
      if (!ctx) {
        await commitDiscordInboundReplay({ replayKeys, replayGuard });
        return;
      }
      applyImplicitReplyBatchGate(ctx, params.replyToMode, false);  // isBatched=false
      queueAcceptedDiscordTypingCue(ctx);
      messageRunQueue.enqueue(buildDiscordInboundJob(ctx, { replayKeys }));
      return;
    }
    // 多条：合并文本
    const combinedBaseText = entries
      .map((entry) =>
        resolveDiscordMessageText(entry.data.message, { includeForwarded: false }),
      )
      .filter(Boolean)
      .join("\n");  // ⭐ 用 \n 拼接
    const syntheticMessage = Object.create(Object.getPrototypeOf(last.data.message), {
      ...Object.getOwnPropertyDescriptors(last.data.message),
      content: { value: combinedBaseText, enumerable: true, configurable: true },
      attachments: { value: [], enumerable: true, configurable: true },  // 清空附件
      // ... 其他字段
    }) as DiscordMessageEvent["message"];
    const syntheticData: DiscordMessageEvent = {
      ...last.data,
      message: syntheticMessage,
    };
    const ctx = await preflight({ ...params, data: syntheticData, client: last.client });
    if (!ctx) {
      await commitDiscordInboundReplay({ replayKeys, replayGuard });
      return;
    }
    applyImplicitReplyBatchGate(ctx, params.replyToMode, true);  // isBatched=true
    if (entries.length > 1) {
      const ids = entries.map((entry) => entry.data.message?.id).filter(isNonEmptyString);
      if (ids.length > 0) {
        const ctxBatch = ctx as typeof ctx & { batchMessageIds?: string[] };
        ctxBatch.batchMessageIds = ids;  // 记录原始消息 ID
      }
    }
    queueAcceptedDiscordTypingCue(ctx);
    messageRunQueue.enqueue(buildDiscordInboundJob(ctx, { replayKeys }));
  } catch (error) {
    // ... 错误处理
  }
},
```

**合并策略**：
- **1 条**：正常处理，`isBatched=false`
- **多条**：
  - 文本用 `\n` join
  - 构造 synthetic message（用最后一条的元数据，content 替换为合并文本，attachments 清空）
  - `isBatched=true` 影响回复策略（`applyImplicitReplyBatchGate`）
  - 记录原始消息 ID 到 `ctx.batchMessageIds`

export function resolveInboundDebounceMs(params: {
  cfg: OpenClawConfig;
  channel: string;
  overrideMs?: number;
}): number {
  const inbound = params.cfg.messages?.inbound;
  const override = resolveMs(params.overrideMs);
  const byChannel = resolveChannelOverride({
    byChannel: inbound?.byChannel,
    channel: params.channel,
  });
  const base = resolveMs(inbound?.debounceMs);
  return override ?? byChannel ?? base ?? 0;  // 优先级：override > byChannel > base > 0
}
```

      "byChannel": {

        "feishu": 600     // feishu 覆盖
      }
    }
  }
}
```

## 关键设计总结

| 维度 | openclaw 方案 |
|------|---------------|
| **合并范围** | 纯文本合并，带图/附件/命令不合并 |
| **合并 key** | `{channel}:{accountId}:{channelId}:{authorId}` |
| **合并窗口** | 可配置（全局 + 按 channel 覆盖），默认 0（不合并） |
| **合并策略** | 多条用 `\n` join 文本，构造 synthetic message（用最后一条元数据） |
| **回复策略** | `isBatched` 标记影响回复行为（`applyImplicitReplyBatchGate`） |
| **原始消息** | 记录 `batchMessageIds` 供后续使用 |

### 2. 关键决策

| 决策项 | openclaw 方案 | 我们可选方案 |
|--------|---------------|--------------|
| **合并范围** | 纯文本合并，带图不合并 | 同上（简单） |
| **合并 key** | `{channel}:{accountId}:{channelId}:{authorId}` | `{channel}:{channel_id}:{from}`（DM 场景 channel_id 为空需处理） |
| **合并窗口** | 可配置，默认 0 | 800ms 起步？ |
| **合并后归属** | 用最后一条元数据 | 同上（简单） |

### 3. 实现路径

1. **移植 `inbound-debounce.ts`** — 改造成 Engine 版本

4. **配置化** — 加 `messages.inbound.debounceMs` 到 config schema
5. **飞书/wechat 接入** — 每个 channel 一个 debouncer
