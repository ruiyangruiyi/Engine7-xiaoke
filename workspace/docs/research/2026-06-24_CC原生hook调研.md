## 一、CC 原生 Hook 系统全景

### 1.1 Hook 类型总览（28 种事件）

| 类别 | 事件名 | 触发时机 |
|------|--------|---------|
| 工具生命周期 | `PreToolUse` | 工具调用前（可拦截） |
| | `PostToolUse` | 工具调用成功后 |
| | `PostToolUseFailure` | 工具调用失败后 |
| 权限 | `PermissionRequest` | 权限请求发起时 |
| | `PermissionDenied` | 权限被拒后 |
| 用户输入 | `UserPromptSubmit` | 用户提交 prompt 时 |
| | `Notification` | 通知事件 |
| Session 生命周期 | `SessionStart` | Session 启动（总触发） |
| | `SessionEnd` | Session 结束 |
| | `Setup` | 初始 setup（总触发） |
| 停止控制 | `Stop` | 模型完成一轮时 |
| | `StopFailure` | 停止失败 |
| Subagent | `SubagentStart` | Subagent 启动 |
| | `SubagentStop` | Subagent 停止 |
| 压缩 | `PreCompact` | 压缩前 |
| | `PostCompact` | 压缩后 |
| Team 协作 | `TeammateIdle` | Team mate 空闲 |

| | `FileChanged` | 文件变化 |

### 1.2 Hook 类型（4 种实现方式）

CC 支持 4 种 hook 实现方式（src/schemas/hooks.ts:31-171）：

| 类型 | 配置字段 | 用途 |
|------|---------|------|
| **`command`** | `command: string` | 执行 shell 命令，JSON stdin/stdout 协议 |
| **`prompt`** | `prompt: string` | LLM 评估（用 `$ARGUMENTS` 占位符） |
| **`agent`** | `prompt: string` | Agentic verifier（运行 subagent 验证） |
| **`http`** | `url: string` | HTTP POST hook 输入到 URL |

**Engine 当前只支持 `command` + 内部 `callback`**（砍掉了 prompt/agent/http）。

### 1.3 Hook 配置文件格式

**位置**（3 个层级，优先级高 → 低）：
- `~/.claude/settings.json` — User settings
- `<project>/.claude/settings.json` — Project settings
- `<project>/.claude/settings.local.json` — Local settings

**格式**（对齐 CC HooksSchema）：
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",   // 可选，glob/regex 匹配 tool_name
        "hooks": [
          {
            "type": "command",
            "command": "echo $CLAUDE_PROJECT_DIR",
            "timeout": 60,
            "async": false
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "python validate.py"
          }
        ]
      }
    ]
  }
}
```

**`if` 条件过滤**（src/schemas/hooks.ts:19-27）：
```json
{
  "type": "command",
  "command": "git status",
  "if": "Bash(git *)"   // 只在 Bash 工具以 git 开头时触发
}
```


### 2.2 Hook 输出（command hook 通过 stdout 返回）

**两类响应**（src/types/hooks.ts:227-243）：

#### A. 同步响应（JSON 格式）

```typescript
interface SyncHookJSONOutput {
  continue?: boolean          // false = 阻止继续
  suppressOutput?: boolean    // true = 隐藏 transcript 输出
  stopReason?: string         // continue=false 时的提示
  decision?: 'approve' | 'block'  // PreToolUse 的权限决策
  reason?: string
  systemMessage?: string      // 给用户的警告
  hookSpecificOutput?: HookSpecificOutput
}
```

**hookSpecificOutput**（按事件类型分类）：
- **PreToolUse**：`permissionDecision` ('allow'|'deny'|'ask'), `permissionDecisionReason`, `updatedInput`, `additionalContext`
- **UserPromptSubmit**：`additionalContext`
- **SessionStart**：`additionalContext`, `initialUserMessage`, `watchPaths`
- **PostToolUse**：`additionalContext`, `updatedMCPToolOutput`
- **PermissionRequest**：`decision: { behavior: 'allow'|'deny', ... }`
- **Stop**：`decision: 'approve'|'block'`

#### B. 异步响应

```typescript
interface AsyncHookJSONOutput {
  async: true
  asyncTimeout?: number
}
```

**CC 重要约定**：
- 退出码 `0` = 成功（解析 stdout JSON）
- 退出码 `2` = **blocking error**（stderr 作为 blocking error 显示给 Claude）
- 其他非 0 = 非阻塞错误

### 2.3 执行模型

**超时**：
- command hook 默认 **10 分钟**（src/services/tools/toolHooks.ts）
- 可在 hook 配置 `timeout` 字段覆盖（秒）
- AbortSignal 支持父调用中止

**并发**：
- 同一事件的多个 hooks **并行执行**（executeHooks 用 Promise.all）
- 多个 matcher 顺序匹配

**prompt/agent hook 的特殊参数替换**：
- `$ARGUMENTS` → 替换为 hook input JSON
- `$ARGUMENTS[0]`、`$0` → 索引访问
- `$ARGUMENTS.field` → 字段访问

### 3.1 触发点（关键路径）

| 事件 | 触发位置 | 文件 |
|------|---------|------|
| `UserPromptSubmit` | handle-query.ts:382 | 用户提交 prompt |
| `PreToolUse` | runPreToolUseHooks | services/tools/toolHooks.ts:435 |
| `PostToolUse` | runPostToolUseHooks | services/tools/toolHooks.ts:39 |
| `PostToolUseFailure` | runPostToolUseFailureHooks | services/tools/toolHooks.ts:193 |
| `Stop` | query/stopHooks.ts | 模型完成一轮 |
| `PreCompact` / `PostCompact` | services/compact/compact.ts | 压缩前后 |
| `SubagentStart` / `SubagentStop` | tools/AgentTool/AgentTool.ts | subagent 生命周期 |
| `SessionStart` / `SessionEnd` | bootstrap/session.ts | session 生命周期 |
| `TaskCreated` / `TaskCompleted` | tools/TaskTool | task 系统 |

### 3.2 执行流程（PreToolUse 为例）

```
tool call requested
  ↓
runPreToolUseHooks(tool, input, toolUseID, ...)
  ↓
executePreToolHooks(tool.name, toolUseID, input, ...)
  ↓
getMatchingHooks('PreToolUse', tool.name)  // matcher 过滤
  ↓
Promise.all([
  executeOneHook(hook1, ...),
  executeOneHook(hook2, ...),
  ...
])
  ↓
aggregateResults(results)  // 合并多 hook 结果
  ↓
返回 AggregatedHookResult {
  message?: string
  blockingError?: { ... }
  preventContinuation?: boolean
  permissionBehavior?: 'allow' | 'deny' | 'ask'
  additionalContexts?: string[]
  updatedInput?: Record<string, unknown>
}
  ↓
toolExecution 处理 permissionBehavior：
  - 'allow' → 跳过权限弹窗
  - 'deny' → 阻止执行
  - 'ask' → 强制用户确认
```

### 3.3 Hook 结果聚合规则（src/utils/hooks.ts aggregateResults）

1. **`blockingError`**：任何一个 hook 失败则整个失败
2. **`permissionBehavior`**：取最后一个非 undefined 的值
3. **`additionalContexts`**：合并所有 hook 的，组成数组
4. **`updatedInput`**：取最后一个 hook 的
5. **`message`**：取最后一个非阻塞的 message

## 五、贴合 CC 原生用法的改造建议

### 5.1 立即可做（贴合度高，成本低）

#### 1. 补齐 `if` 条件过滤

**现状**：config.ts 只支持 matcher glob，没实现 `if` permission-rule 语法

**建议**：在 `getMatchingHooks` 里加 `if` 评估逻辑

```typescript
function matchesIf(ifPattern: string | undefined, hookInput: HookInput): boolean {
  if (!ifPattern) return true
  // 解析 "Bash(git *)" → 检查 tool_name 匹配 + tool_input 包含 git
  const match = ifPattern.match(/^(\w+)\((.+)\)$/)
  if (!match) return true
  const [, toolPattern, inputPattern] = match
  // ... 用 minimatch 匹配
}
```

#### 2. 接入 PreToolUse / PostToolUse 到工具执行循环

**现状**：`toolExecution` 里完全没调 `executePreToolHooks`

**建议**：在 `handle-query.ts` 或工具分发层包装调用

```typescript
// 工具执行前
const preResult = await executePreToolUseHooks(toolName, toolInput, ctx, signal)
if (preResult.permissionBehavior === 'deny') {
  yield { type: 'hookPermissionResult', hookPermissionResult: preResult }
  return
}
if (preResult.permissionBehavior === 'allow') {
  // 跳过权限弹窗
}
if (preResult.updatedInput) {
  toolInput = preResult.updatedInput
}

// 工具执行后
const postResult = await executePostToolUseHooks(toolName, toolInput, toolOutput, ctx)
if (postResult.additionalContexts?.length) {
  // 注入到下次模型调用
}
```

#### 3. 支持 `SessionStart.initialUserMessage`

**现状**：`executeSessionStartHooks` 调了，但结果没被消费

**建议**：在 session 创建时检查 aggregated.initialUserMessage，有就作为首条 user 消息

#### 4. 支持 `PostToolUse.updatedMCPToolOutput`

**现状**：aggregator 收了但 executor 没透传

**建议**：在 MCP 工具执行后链上 `result.updatedMCPToolOutput`

### 5.2 中期改造（贴合度提升大）

```typescript
async function execPromptHook(hook: PromptHook, jsonInput: string): Promise<SyncHookJSONOutput> {
  const prompt = addArgumentsToPrompt(hook.prompt, jsonInput)

    responseSchema: z.object({ ok: z.boolean(), reason: z.string().optional() })

}
```
