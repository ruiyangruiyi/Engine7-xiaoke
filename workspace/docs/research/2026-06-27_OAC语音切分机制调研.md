# OAC 语音切分机制调研报告

**日期：** 2026-06-27
**调研目的：** voice-chat 连续说话时消息碎片化（12条排队），调研 OAC 如何处理

## 问题

人说话天然会停顿，VAD 每检测到一段语音就触发 ASR → 独立消息 POST → engine 队列疯涨。
需要一种机制判断"用户是真的说完了，还是只是停顿"。

## OAC 三层切分机制

### 第一层：POST_END 状态机（核心）

OAC 的 VAD 不是简单的"说话→静音→结束"，而是四状态：

```
PRE_START → START → END → POST_END
```

**POST_END 是关键创新：**

1. 检测到静音后不立即结束，进入 POST_END 状态
2. POST_END 继续监听音频，持续 `post_end_monitor_samples`（默认 16000 samples = 1 秒）
3. 期间检测语音用双重机制：
   - VAD 模型检测（speech_length > 0）
   - 能量检测备份（current_db > -35dB）
4. 如果 POST_END 期间检测到新语音：
   - 且间隔 < `reconnect_threshold_samples`（默认 8000 = 0.5 秒）→ **重连**
   - 且间隔 >= 0.5 秒 → 认为是新的独立语音
5. POST_END 超时（1 秒无新语音）→ 确认说完了

**关键参数（SileroVADConfigModel）：**
```python
end_delay = 5000          # 正常结束的静音阈值（samples）
early_end_delay = 1500    # 早期结束检测（触发 EOU）
post_end_monitor_samples = 16000  # POST_END 监控期 = 1 秒
reconnect_threshold_samples = 8000  # 重连阈值 = 0.5 秒
post_end_energy_threshold = -35.0  # POST_END 能量检测阈值（dB）
volume_threshold = -40.0  # 音量阈值（dB）
```

### 第二层：Smart Turn EOU 模型（语义判断）

**目的：** VAD 只看音频特征，EOU 模型判断语义是否完整。

**工作流程：**
1. VAD 在静音 `early_end_delay`（1500 samples ≈ 0.09 秒）时发 `EVT_EARLY_VAD_END` 事件
2. EOU handler 收到事件后，用 smart-turn-v3.1 ONNX 模型预测
3. 取最近 8 秒音频，Whisper feature extractor 提特征 → ONNX 推理
4. 输出：`probability > threshold(0.5)` → 说完了 → 发 `STREAM_END` 信号给 VAD
5. 没说完 → 等下一个 early_vad_end（VAD 会持续发送）

**信号机制：**
- EOU → VAD: `candidate STREAM_END`（"我觉得说完了，你确认下"）
- VAD → EOU: `EVT_EARLY_VAD_END`（"用户停了一下，你判断下"）
- VAD 还可以收 `SEMANTIC_WAIT` 信号延长等待

### 第三层：音频累积 + 重连

**问题：** POST_END 期间发现误切怎么办？上一个 stream 已经发给 ASR 了。

**OAC 的解法：cancel + 重发**

1. `accumulated_speech_audio` 从说话开始一直累积所有 clips
2. POST_END 检测到重连触发时：
   - cancel 上一个 stream（级联 cancel 所有下游 stream）
   - 重新启用 VAD
   - 把 `accumulated_speech_audio` 里所有 clips 发到新 stream
3. 即使多次重连也不丢音频，ASR 拿到的是完整音频

```python
# 重连核心逻辑
if reconnect_triggered:
    cancel_stream(previous_stream_id)
    input_enabled = True
    for clip in accumulated_speech_audio:
        submit_data(clip)  # 重发到新 stream
```
