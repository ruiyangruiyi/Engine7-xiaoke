## 核心决策

### 1. 配置文件位置：跟着 stateDir 走

**问题**：现在 configs/ 在源码目录里，生产环境不行。

**方案**：一个 agent 一个目录，config 和 state 放一起。

```
D:/my-agent/
├── configs/
│   └── main.json
├── state/
│   └── agents/main/sessions/
├── workspace/
│   ├── SESSION-STATE.md
│   ├── HEARTBEAT.md
│   ├── SOUL.md
│   └── prompts/contacts.md
└── logs/
```

**好处**：
- 多用户多租户天然支持（潘总一个、我们自己一个）
- 源码干净（不混客户配置）
- 客户出问题打包 `D:/my-agent/` 发来直接解压复现
- 跟 L2 远程诊断方案（打包 ~/.engine7/ 发来）配套

### 2. 初始化脚本：`engine7 init`

```bash
engine7 init --state-dir D:/my-agent
```

**功能**：
- `--state-dir` 支持相对路径（用户在 cmd 里不需要写绝对路径）
- 交互式 prompt 分两步：
  1. 必填：provider、API key
  2. 可选：bot token、cron 配置等
- `--quick` 模式：用默认配置跳过交互
- `--dry-run`（P2）：显示会创建什么不真创建
- **schemaVersion 字段**：第一次 init 写 v1，以后升级时检测 v1 → v2 自动迁移

**创建的目录结构**：
```
D:/my-agent/
├── configs/
│   └── main.json          ← 从模板生成，提示填 API key
├── state/
│   └── agents/main/sessions/
├── workspace/
│   ├── SESSION-STATE.md   ← 空模板
│   ├── HEARTBEAT.md       ← 空模板
│   ├── SOUL.md            ← 空模板
│   └── prompts/
│       └── contacts.md    ← 空模板
└── logs/
```

### 3. 导入现有配置：`engine7 import`

```bash
engine7 import --from C:/Users/24045/.openclaw/engine/configs/main.json
```

**定位**：为非技术用户准备的「一键迁移工具」—— 不是给开发者用的（开发者直接 mv + 改 JSON 就行）

**核心价值**：
- 智能路径迁移（自动改 main.json 里的 stateDir/workspaceDir/logDir）
- 自动备份原文件（改完出问题能回滚）
- dry-run 预览（让用户先看改了啥再确认）

**本地 vs URL**：
- **本地版（v0.1）**：`--from <local-path>`，同机器内迁移
- **URL 版（v1.1 TODO）**：`--from https://oss.example.com/bundle-2026-06-19.tar.gz`，跨机器迁移（换电脑场景），需签名验证 + 自动备份脚本

**用途**：给老客户（我们自己就是）从旧路径升级用。
