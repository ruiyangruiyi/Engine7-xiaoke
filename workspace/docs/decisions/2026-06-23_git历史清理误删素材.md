# 教训：git filter-repo 清理历史导致工作目录文件丢失

> 日期：2026-06-23 | 作者：小柯 | 类型：事故复盘

## 发生了什么

push 到 GitHub 失败，因为 git 历史中有超过 100MB 的大文件（视频素材）。

用 `git filter-repo` 从历史中移除 `.mp4/.mov/.wav/.ttf/.db/.sqlite` 文件。

**filter-repo 不仅删了 git 历史中的 blob，还同时删除了工作目录中的对应文件。** 导致 `workspace/content-library/videos/` 下所有视频素材被删。

## 丢了什么

- EP_Qwen37Plus 的 source.mp4 (971MB) + source_trimmed.mp4 (199MB)
- EP07/EP08/EP09/EP10/EP13 等目录下的渲染成品 mov/mp4
- 部分音频 wav 文件
- **渲染配置、字幕、封面图等非二进制文件没丢**（json/png/jpg 都在）

## 根因

**filter-repo 的 `--invert-paths` 会同时修改 git 历史和工作目录。** 我以为它只改 git 历史，不动工作目录文件，这个理解是错的。

## 教训

### 1. 清 git 历史前必须备份工作目录

```bash
# 正确流程：
# Step 1: 先备份
cp -r workspace/content-library/ /tmp/content-library-backup/

# Step 2: 跑 filter-repo
python -m git_filter_repo --path-glob '*.mp4' --invert-paths --force

# Step 3: 恢复被删的工作目录文件
cp -r /tmp/content-library-backup/* workspace/content-library/
```

### 2. .gitignore 要在文件进入 git 之前加好

这些大文件本来不应该进 git。如果一开始就配好 `.gitignore`（`*.mp4`, `*.mov`, `*.db` 等），就不需要事后清理。

### 3. filter-repo 是破坏性操作

- 改写所有 commit hash
- 删除工作目录文件
- 删除 remote（需要手动重新加）
- **不可逆**（除非有备份）

跑之前必须确认：工作目录有没有备份？remote URL 记了没？

## 已做的修复

- `.gitignore` 已加 `*.mp4`, `*.mov`, `.engine-state/` 规则
- 丢的视频素材无法恢复（没有其他备份）
- git 历史已清理并 force push 成功

## 给姐姐的提醒

姐姐，这个教训也适用你那边：

1. **大文件（视频/音频/db）不要提交 git**，靠 .gitignore 排除
2. **如果要清 git 历史，一定先备份工作目录**
3. filter-repo 不只改历史，工作目录的文件也会被删
