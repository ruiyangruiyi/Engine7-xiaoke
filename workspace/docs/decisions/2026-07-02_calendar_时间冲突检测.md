# Calendar 时间冲突检测 + per-task notification route

> 2026-07-02 小柯设计，翀哥确认

## Part 1: 时间冲突检测

### 需求

1. **普通日程（date + weekly）加时间段**：start_time + duration（必填，不填拒绝）
2. **冲突策略**：
   - 日程 vs 日程：时间段重叠 → **拒绝**（带冲突理由）
   - task vs task：time_exact 在 30min 内 → **警告**（不阻止）

### Schema 变更

```
ALTER TABLE events ADD COLUMN start_time TEXT        -- '14:00'
ALTER TABLE events ADD COLUMN duration_min INTEGER   -- 60（分钟）
```

### 冲突检测逻辑

**日程 vs 日程**（date + weekly）：
```
两个时间段重叠：start < otherEnd && end > otherStart → 拒绝
冲突消息：❌ 时间冲突：14:30-15:30 与 #28「周会」(14:00-15:00) 重叠
```

**task vs task**：
```
|taskA_time - taskB_time| < 30min → 警告（不阻止）
警告消息：⚠️ 时间接近：与 #30「task A」(14:00) 仅相差 15min
```

### duration 格式

`30m` / `1h` / `90m`（跟 remind 格式一致）

### 改动文件

| 文件 | 改动 |
|------|------|
| `db.ts` | migrate 加 start_time + duration_min |
| `helpers.ts` | parseDuration + checkScheduleConflict + checkTaskProximity |
| `commands.ts` | addDate/addWeekly 加必填校验 + 冲突拒绝；addTask 加 30min 警告 |
| `calendar.ts` | tool schema 加 duration 参数 |

### 不改的

- task 不加 duration（任务是时间点，不是时间段）
- 已有数据（无 start_time/duration_min）冲突检测跳过
- remind 逻辑不变

## Part 2: Per-task notification route（删 lastMain）

### 背景

notification 投递原本依赖全局 `lastMainChannelTarget`（记录"最后一条用户消息来的频道"），有多个问题：
1. channel/target 不匹配（target 是飞书 id，channel 写死 discord）
2. 多平台覆盖（飞书聊完切 Discord，lastMain 被覆盖）
3. 客户群风险（客户群消息更新 lastMain → notification 发到客户群）

### 方案：per-task route

每个 notification 自带 route（channel + target），不依赖全局状态。

| 路径 | route 来源 | 存储 | 原因 |
|------|-----------|------|------|
| bash bg task | ctx | 内存 TaskState | task 跟进程同生命周期 |
| calendar task | ctx | DB events 表 | reminder 可能几天后触发 |

投递规则：**无 route 不投递**（宁可丢弃也不发到错误频道）

### 改动文件

| 文件 | 改动 |
|------|------|
| `calendar/db.ts` | 加 created_channel + created_channel_target 列 |
| `calendar/commands.ts` | addTask 存 route |
| `calendar/reminder-plugin.ts` | 从 DB 读 per-task route，逐条投递 |
| `tools/task-manager.ts` | kill 补 route |
| `tools/calendar.ts` | add-task 传 ctx route |
| `engine-startup.ts` | 删 lastMain 整套 |

详见 engine/docs/notification-route-per-task.md
