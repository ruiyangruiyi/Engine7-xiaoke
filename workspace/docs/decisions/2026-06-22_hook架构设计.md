# Hook 架构设计

> 日期：2026-06-22 | 作者：小柯 | 决策者：翀哥

## 背景

engine 主流程混了太多 inline 硬编码逻辑——onResult 里 3 个 if 分支 + 1 次额外 LLM 调用，onMessage 里 120 行附件处理。每加一个功能（OAC webhook、外部群规则、msgGuard）都要改主流程代码。

翀哥要求：加 hook 架构，后面所有拦截逻辑走 hook 注册，不改主流程。

## 设计

### 两个 hook 点位

```
消息进来 → [PreQueryHook] → LLM → [OnResultHook] → 发出去
```

| Hook | 位置 | 时机 | 能力 |
|------|------|------|------|
| **PreQueryHook** | `dispatcher.submitMessage` 前 | 消息进来后、入队前 | 改消息内容、注入上下文、拦消息（return null）、改 msgDeps（如切 model） |
| **OnResultHook** | `channelManager.send` 前 | LLM 回复后、发出去前 | 改回复内容、拦回复（return null）、改 send opts |

### Hook 接口

```typescript
// src/hooks/types.ts

export interface HookContext {
  /** 入站消息元数据 */
  inbound: {
    channel: string         // 'discord' | 'feishu' | 'weixin' | 'oac'
    channel_id: string
    from: string
    fromName?: string
    channelType?: 'dm' | 'group'
    isMentioned?: boolean
  }
  /** engine config（只读引用） */
  config: EngineConfig
  /** 工具依赖（provider、channelManager 等） */
  deps: HookDeps
}

export interface PreQueryContext extends HookContext {
  /** 消息文本（可改） */
  text: string | ContentBlock[]
  /** 附件（只读） */
  attachments?: InboundAttachment[]
  /** msgDeps（可改，如 vision 路由切 model） */
  msgDeps: HandleQueryDeps
}

export interface PreQueryResult {
  /** 改后的文本/blocks（不改就 return 原 text） */
  text?: string | ContentBlock[]
  /** 改后的 msgDeps（不切 model 就不传） */
  msgDeps?: HandleQueryDeps
  /** return null = 拦截，不进 LLM */
  skip?: boolean
}

export type PreQueryHook = (ctx: PreQueryContext) => Promise<PreQueryResult | null | void>

export interface OnResultContext extends HookContext {
  /** LLM 回复文本（可改） */
  response: string
  /** send options（可改，如 replyTo） */
  sendOpts?: SendOptions
}

export interface OnResultResult {
  /** 改后的回复（不改就不传） */
  response?: string
  /** 改后的 opts */
  sendOpts?: SendOptions
  /** return null = 拦截，不发出去 */
  skip?: boolean
}

export type OnResultHook = (ctx: OnResultContext) => Promise<OnResultResult | null | void>
```

### Hook 注册

```typescript
// src/hooks/registry.ts

export class HookRegistry {
  private preQueryHooks: Array<{ name: string; fn: PreQueryHook; priority: number }> = []
  private onResultHooks: Array<{ name: string; fn: OnResultHook; priority: number }> = []

  registerPreQuery(name: string, fn: PreQueryHook, priority = 50): void
  registerOnResult(name: string, fn: OnResultHook, priority = 50): void

  async runPreQuery(ctx: PreQueryContext): Promise<PreQueryResult>
  async runOnResult(ctx: OnResultContext): Promise<OnResultResult>
}
```

**priority**：0-100，数字小先跑（0 最先，100 最后）。默认 50。

**链式执行**：前一个 hook 的输出是后一个的输入。任何一个 `skip=true` 就终止链。

### 主流程改动

#### onMessage lambda（PreQueryHook 执行点）

```typescript
// engine-startup.ts onMessage lambda 里，dispatcher.submitMessage 前

// 6/22 hook 架构：PreQuery 链
const hookResult = await hooks.runPreQuery({
  inbound: { channel: inbound.channel, channel_id: inbound.channel_id, from: inbound.from, ... },
  text: queryContent,
  attachments: inbound.attachments,
  msgDeps,
  config,
  deps: { provider, channelManager, sessions, ... },
})

if (hookResult.skip) {
  console.log(`[hooks] PreQuery ${inbound.from} skipped`)
  return  // 不进 dispatcher
}

queryContent = hookResult.text ?? queryContent
if (hookResult.msgDeps) msgDeps = hookResult.msgDeps

dispatcher.submitMessage({ text: queryContent, ... })
```

#### onResult callback（OnResultHook 执行点）

```typescript
// engine-startup.ts onResult callback 里，channelManager.send 前

// 6/22 hook 架构：OnResult 链
const resultHook = await hooks.runOnResult({
  inbound: { channel: inbound.channel, ... },
  response: finalResponse,
  sendOpts: opts,
  config,
  deps: { provider, channelManager, ... },
})

if (resultHook.skip) {
  console.log(`[hooks] OnResult ${inbound.channel_id} skipped`)
  return  // 不发出去
}

finalResponse = resultHook.response ?? finalResponse
opts = resultHook.sendOpts ?? opts

channelManager.send(inbound.channel, inbound.channel_id, finalResponse, opts)
```

## 风险

1. **敏感词过滤内部会反向 submitMessage**（回灌系统通知）——hook 要支持"注入反馈"，不能死循环
2. **附件处理 120 行暂不抽**——改动太大，先验证 hook 机制 work 再抽
3. **现有 `executeUserPromptSubmitHooks`（handle-query.ts:380）** 是 CC 兼容的 shell hook，和 PreQueryHook 并行存在，不合并
