## 1. 背景与问题

### 现状
- 通信规则（不喊老公、msgGuard 拦截词等）靠人记
- 上下文多了容易忘，导致违规
- 规则散落在 MEMORY.md、AGENTS.md、contacts.md 多处

### 目标
- 规则自动跟随消息注入，不用人记
- 每条消息自带该频道的通信规则
- 系统 prompt 能看到规则，不会忽略

---

## 2. 核心设计

### 2.1 数据流

```
contacts.md (规则配置)
    ↓ 启动时加载
ChannelRulesLoader (解析规则)
    ↓ 缓存规则表
消息处理层 (收到 InboundMessage)
    ↓ 根据 channel_id 匹配规则
msg.metadata.content_blocks (注入规则 block)
    ↓ 传给 agent
系统 prompt 显示规则 (agent 看到)
```

### 2.3 规则匹配优先级

```
1. 精确匹配 channel_id（最高优先）
2. 匹配 channel_type（dm/group）
3. 默认规则（兜底）
```

规则可叠加：
- 通用规则（DM 规则）+ 群特定规则（外部群规则）
- 后定义的覆盖先定义的（同名 key）

## 3. 技术实现

### 3.1 新增模块：`src/channels/channel-rules.ts`

```typescript
export interface ChannelRule {
  name: string  // 规则名（如"飞书外部群"）
  channel_ids?: string[]  // 匹配的 channel_id 列表
  channel_type?: 'dm' | 'group'  // 匹配的 channel 类型
  rules: string[]  // 规则文本列表
  msgGuard?: string[]  // 拦截词列表
}

export class ChannelRulesLoader {
  private rules: ChannelRule[] = []
  
  /** 从 contacts.md 加载规则 */
  loadFromContacts(contactsPath: string): void
  
  /** 根据 channel_id 和 channel_type 匹配规则 */
  matchRules(channelId: string, channelType?: 'dm' | 'group'): ChannelRule | null
  
  /** 获取规则文本（用于注入 metadata） */
  getRulesText(channelId: string, channelType?: 'dm' | 'group'): string
}
```

### 3.2 修改 InboundMessage 类型

在 `src/channels/types.ts` 的 `InboundMessage` 接口加：

```typescript
export interface InboundMessage {
  // ... 现有字段
  
  /** 平台特有元数据（adapter 自用，engine 不碰） */
  metadata?: Record<string, string> & {
    content_blocks?: Array<{
      type: string
      content: string
    }>
  }
}
```

### 3.3 消息处理层注入

在 `src/channels/manager.ts` 的 `onMessage` 回调里：

```typescript
adapter.onMessage((msg) => {
  // 注入通信规则到 metadata.content_blocks
  const rule = rulesLoader.matchRules(msg.channel_id, msg.channelType)
  if (rule) {
    if (!msg.metadata) msg.metadata = {}
    if (!msg.metadata.content_blocks) msg.metadata.content_blocks = []
    
    // 构建规则文本
    const rulesText = rule.rules.join('\n')
    let blockContent = `## 当前频道通信规则\n${rulesText}`
    
    if (rule.msgGuard && rule.msgGuard.length > 0) {
      blockContent += `\n\n**msgGuard 拦截词：** ${rule.msgGuard.join('、')}`
    }
    
    // push 新 block
    msg.metadata.content_blocks.push({
      type: 'communication_rules',
      content: blockContent,
    })
  }
  
  // 继续原有处理
  this.handleMessage(msg)
})
```

### 3.4 系统 prompt 显示规则

在 `src/prompt.ts` 的 `buildStablePrompt` 里：

```typescript
// 如果有 channelRules block，加到 system prompt
if (currentMessage?.metadata?.content_blocks) {
  const rulesBlock = currentMessage.metadata.content_blocks.find(
    b => b.type === 'communication_rules'
  )
  if (rulesBlock) {
    prompt += `\n\n${rulesBlock.content}`
  }
}
```

## 6. 风险与对策

### 风险 1：contacts.md 格式复杂，用户配错
**对策：**
- 提供配置示例和校验工具
- 启动时校验格式，错误时 warn 但不 crash

### 风险 2：规则太多，系统 prompt 超长
**对策：**
- 只显示当前消息的规则，不显示所有规则
- 规则文本控制在 500 字以内

### 风险 3：msgGuard 拦截词误判
**对策：**
- 拦截词用精确匹配，不用模糊匹配
- 提供白名单（如"翀哥的老婆"不拦截，只拦截"老婆"）
