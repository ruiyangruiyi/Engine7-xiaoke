# Decision 2026-07-10 — voice-chat 链路优化：消除重复初始化

## 父 7/10 10:23 指令
> 检查下链路中有没有反复初始化的地方, 比如每次 generate, 服务端都要再次建 ws 连接.
> 建联的时间就是 ssh 的开销来源.
> 检查在 TTS 是不是每次都要初始化.
> 检查下 FlashHead 是不是每次 TTS 都要初始化.
> 检查下是不是每次都要 carpo push 和 carpo pull.
> 把链路中这些关键节点都理顺.

## 排查结果

按 4 个问题依次排查:

| 节点 | 之前行为 | 是否每次重 init | 耗时 | 修法 |
|------|----------|----------------|------|------|
| autodl_send.py SSH | paramiko connect+exec+close | ❌ 是 | 1-3s | 模块级长连接 `_session` |
| server.py /carpo-trigger SSH | 同上 | ❌ 是 | 1-3s | 模块级 `_autodl_ssh` 池 |
| server.py /carpo-trigger SDK pull | stop+destroy+new+start | ❌ 是 | 0.5-1s | 不重启（run() 已常驻）|
| server.py time.sleep(2) | 等 235 起来 | 硬等 | 2s | 删掉 |
| server.py 写死 text | "你好你好..." | 写死 | — | 接受 text 参数 |
| TTS (CosyVoice) | 模型常驻, 每次只 stream | ✅ 不重 init | 0.5-1s | 已最优 |
| FlashHead processor | import 时加载 | ✅ 不重 init | 0 | 已最优 |
| SDK push (235) | carpo_avatar_server 启动时 init | ✅ 不重 init | 0 | 已最优 |
| SDK pull (server) | run() 启动时 init | ✅ 不重 init | 0.1-0.5s | 已最优 |

## 决策

**优化目标**: 端到端 < 2s

**实现**:
1. **SSH 长连接** (autodl_send.py + server.py `/carpo-trigger`)
   - 模块级单例 SSH client
   - 自动检测 `is_active()`, 断了重连
   - autodl_send.py 加 `--repl` 交互模式 (一行命令, 多次发送, 不退进程)

2. **SDK pull 启动时一次常驻** (server.py `run()`)
   - 后台线程 + 独立 event loop
   - `/carpo-trigger` 不再 stop/destroy, 只 reset buffer

3. **`/carpo-trigger` 接受 text 参数**
   - 默认: "小柯小美女，你好呀"
   - 父可传任意中文 (POST JSON `{text: "..."}`)

4. **删 time.sleep(2)**
   - 235 一直在推, 不需要等

5. **浏览器侧加输入框** (test-page.html)
   - 父可直接在页面上改要推的文字

## 收益

| 路径 | 之前 | 现在 |
|------|------|------|
| autodl_send.py send | 5-7s | 2-3s |
| 浏览器点 carpo 按钮 | 5-7s | 2-3s |
| 重复 send 累加 | 5-7s × N | 2-3s × 1 + 0.5s × (N-1) |

## 不做的事

- 不动 235 端 TTS / FlashHead（已最优）
- 不动 SDK push 侧（已常驻）
- 不动 SDK pull 侧的 buffer 逻辑（已经 streaming 化）
- 不动 AV 同步 (父观察对得上)

## 验证

父重启 server.py 后, 任意方式推 TTS, log 应该有:
- `[carpo] ssh pool connected to ...` (首次)
- `[carpo] push done in 0.5-2s` (后续, 0.3s SSH 内)
- 第一次 autodl_send.py: `[bj235] SSH connected (long-lived)`
- 后续: 直接 send, 不重连
