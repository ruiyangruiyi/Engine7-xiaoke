# Decision 2026-07-10 — 端到端时延收集

## 父 7/10 10:39 指令
> 我们开始优化整个链路. 从收到 generate 请求, 到 TTS, 到 flashhead, 到 carpo push, 把这个链路延迟每一步都严格收集上来. 我们之前有个端到端延迟的窗口在浏览器上, 都加进去.

## 链路时延字段定义

| 字段 | 谁打 | 时钟 |
|------|------|------|
| t_request_received | 235 /generate endpoint | unix time.time() |
| t_tts_first_chunk | 235 tts_cosyvoice_streaming | unix time.time() |
| t_tts_last_chunk | 235 generate() | unix time.time() |
| t_flashhead_first | 235 (没在 push 路径上, 留空) | - |
| t_push_audio_first | 235 _push_worker | unix time.time() |
| t_push_video_first | 235 _push_worker | unix time.time() |
| t_request_returned | 235 generate() | unix time.time() |
| t_ssh_exec_start | server.py /carpo-trigger do_push | monotonic |
| t_pull_audio_first | server.py _carpo_on_media | monotonic |
| t_pull_video_first | server.py _carpo_on_media | monotonic |
| t_decode_audio_first | server.py Opus decode | monotonic |
| t_decode_video_first | server.py H264 decode | monotonic |
| t_emit_audio_first | server.py handler.emit | monotonic |
| t_emit_video_first | server.py handler.video_emit | monotonic |
| t_play_audio_browser | browser audio.playing event | performance.now() |
| t_play_video_browser | browser video.playing event | performance.now() |
| t_send_command_browser | browser carpoPush() | performance.now() |

## 时钟对齐

**unix time.time() 在 235/本机都能对比** (假定 NTP 同步, 误差 < 100ms)
**monotonic 在 server.py 内部用** (相对值, 跟 235 不可直接比较, 但 server 内部差值准)
**performance.now() 在浏览器用** (跟 monotonic 类似, 跟 235 需通过 server 中转)

## 数据流向

```
235 /generate (返回 timing JSON)
    ↓ HTTP response
server.py /carpo-trigger do_push  (SSH response 含 timing)
    ↓ asyncio.run_coroutine_threadsafe
_broadcast("timing_235")  → SSE /events  → 浏览器 latencyData.t235

server.py 内部
    每 1.5s: _timing_report_loop() → _take_timing_snapshot() → broadcast("latency")
    → 浏览器 latencyData.serverTiming

浏览器 audio.onplay / video.onplay
    → latencyData.t_play_audio_browser / t_play_video_browser

浏览器 carpoPush() 点击
    → t_send_command_browser = performance.now()
```
