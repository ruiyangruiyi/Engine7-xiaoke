# vision 模型错误处理

## 背景

vision 模型现在的错误处理太重：API 层 3 次 × 每轮 10 次 retry，没 fallback。

主模型已经有 fallback（provider/model 列表 + 多轮重试），vision 没这个能力。

## 现状

- 3 次 API retry × 10 轮 = 最多 30 次尝试
- 没有 fallback
- 失败后用户没明显提示，要手动 `/vision-model` 换

## 期望行为（翀哥 6/19 定）

**能 fallback 的话跟主模型一样：**
- 路由到下个 provider/model
- 多模型列表配置

**不能 fallback 就重试一次：**
- API 1 次 → 失败 → 再 1 次 → 都失败 → 报错
- 报错后用户手动 `/vision-model`

## 实现方向

1. vision 路由加 model 列表配置（参考主模型的 providers/models 配置）
2. retry 简化：失败后 fallback 下一个，都失败报错
3. `/vision-model` 命令已有，不动
4. 错误信息提示用户手动换模型
