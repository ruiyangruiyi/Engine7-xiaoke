# 消息队列合并回复

## 背景

翀哥发消息快、AI回复慢（网络/大模型响应），导致连续多条消息各自独立回复，内容割裂。

## 场景

```
翀哥 08:00:01 | "小柯"
翀哥 08:00:03 | "帮我看看那个bug"
翀哥 08:00:05 | "就是昨天说的那个"
→ 小柯应该一次性看到三条，合并回复
→ 而不是分别回复三次
```

## 现状

`message-queue.ts` 已有消息队列（MessageQueue），消息进来排队。但当前调度逻辑可能是收到一条就处理一条。

## 方案

回复前检查队列里有没有**同一发送者+同一通道**的待处理消息：
- 有 → 取出来合并成一条，一起处理
- 没有 → 正常处理

关键判断字段：
- `source` — 同一来源（discord/feishu/wechat）
- `sender_id` — 同一个人

⚠️ **不用channel_id做判断** — DM场景channel_id为空，用channel会漏掉DM合并。source+sender_id一样就是同一个人在同一个通道发的。

### 实现位置

`core/message-dispatcher.ts` 或 `core/message-queue.ts`：
- 消息出队时，检查队列里有没有同源的后续消息
- 有的话等一小段（如500ms-1s）批量取出
- 合并文本后作为一条消息处理

### 注意

- 合并窗口不能太长，否则感觉迟钝（建议500ms-1s）
- 不同人/不同通道的消息不合并
- 心跳/cron消息不参与合并

## 优先级

跟外部脚本注入一起，属于Engine体验优化。可以先调研message-queue.ts现有调度逻辑。
