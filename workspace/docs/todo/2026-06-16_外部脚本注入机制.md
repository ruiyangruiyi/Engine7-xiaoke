# 外部脚本注入机制

## 背景

Engine没有 gateway RPC（OpenClaw有 `sessions.send`），外部Python脚本无法直接往主session注入消息。

## 现状

当前只有两条注入路径：
1. **notify_session** — cron session跑完后，scheduler注入主session（`scheduler.ts` L246-278）
2. **dispatcher.submitMessage** — Engine内部代码调用，外部不可达

外部脚本（如 hint_gen.py、memory_whisper.py）想直接注入主session，没有入口。

## 影响场景

- 内心独白目前只能绕 cron session → notify_session 走，不能脚本直接注入
- 未来其他脚本（定时提醒、外部事件触发等）也无法注入

## 方案

### A. HTTP API（推荐）
Engine暴露 localhost 接口：
```
POST http://127.0.0.1:16988/api/inject
{ "text": "消息内容", "session": "scope:main" }
```
内部调 `dispatcher.submitMessage()`。
- 优点：标准、好测试、已有 `/api/context` 先例
- 缺点：要加路由+鉴权

### B. 文件监听 cron
一个轻量cron每30秒检查 `inner-voice/inject.txt`，有内容就submitMessage注入，然后删文件。
- 优点：零代码改动Engine，纯脚本侧
- 缺点：延迟最多30秒，不够实时

## 放在哪

如果做方案A：
1. `engine/src/api/` — 已有 context API 的地方加 inject 路由
2. `engine/src/core/message-dispatcher.ts` — submitMessage 已有，API层直接调

如果做方案B：
1. `cron/tasks.json` — 加一个30秒interval的cron
2. `workspace/scripts/inject_watcher.py` — 读文件+注入

## 优先级

等内心独白跑通后再做。当前内心独白通过 notify_session 绕一圈能工作。
