# 配置热加载 #121

## 背景

改完 `configs/xiaoke.json` 后要重启 engine 才能生效，麻烦。已有 `/reload` 斜杠命令（`engine-startup.ts:1290`），但要手动触发。

## 现状

`/reload` 已实现，刷新 6 类字段：
1. recall/extract provider（记忆系统）
2. topics 配置
3. display 配置
4. autoDream 配置
5. features 开关
6. providers 字典

**未刷新**：
- voiceChat plugin（pluginManager 启动时注册）
- cron 任务（启动时调度）
- channels 配置（飞书/discord 连接器）
- api.port
- services 配置（service tool 用的字符串命令）

## 目标

**改 config 文件 → engine 自动检测 → 自动调 `/reload` 逻辑**

不用重启，不用手动 `/reload` 命令。

## 方案

**选 fs.watch（事件驱动，不加依赖）+ debounce 500ms**

### 为什么选 fs.watch

- 引擎是 Node.js，fs.watch 原生支持，零依赖
- 事件驱动，反应快
- 翀哥说过"能不引入新依赖就别加"

### debounce 必要性

编辑器保存通常触发多次事件（先写 tmp、再 rename），500ms debounce 避免 reload 风暴。

### 实现位置

放在 `engine-startup.ts` 启动时，跟 pluginManager/cron 一块初始化。watcher 启动一次，整个进程生命周期有效。

### reload 路径

**不调 `/reload` 斜杠命令**（要飞书通道），直接复用 `/reload` 的核心逻辑——提取 `doReloadConfig()` 函数，让 `/reload` 斜杠命令和 watcher 都能调。

## 实现步骤

1. **重构** `engine-startup.ts:1290-1369` 的 reload 逻辑，提取为 `async function doReloadConfig(configPath)` 复用
2. **加 watcher**：在 startup 末尾（启动完所有 service 后），加 `fs.watch(savedConfigPath, { persistent: true }, debouncedReload)`
3. **debounce**：500ms 内多次触发只 reload 一次
4. **日志**：reload 触发时打 `[config-watch] file changed, reloading...`
5. **错误处理**：reload 失败时打 error，不崩进程

## 验证

1. 启动 engine
2. 改 `configs/xiaoke.json`（比如改 providers 里的某个 apiKey）
3. 5 秒内看到 log: `[config-watch] file changed, reloading...` + `[reload] Config reloaded: ...`
4. 验证 reload 成功（不重启 engine）

## 不做的

- 不加 chokidar 依赖
- 不支持 hot reload voiceChat / channels / api.port
- 不做 GUI 提示
