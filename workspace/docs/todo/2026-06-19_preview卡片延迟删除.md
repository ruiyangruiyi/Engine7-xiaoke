# preview 卡片延迟删除

## 背景

现在 preview 卡片行为：
- onResult 时 freeze（停止流式编辑）
- 然后删除卡片，直接发最终文本

**问题：** 客户视角看——"怎么刚才还在编辑的消息没了？"。体验割裂，可能客户会觉得"消息丢了"。

## 现状

- preview 流式编辑卡片
- onResult → freeze（停止编辑）
- 立刻删除卡片 → 发最终文本
- 这个"删除+再发"动作用户看得见

## 期望行为（翀哥 6/19 定）

**不立马删除卡片，等 2 秒再删，只留文字。**

效果：
- 用户看到流式编辑
- 看到最终文本出现（同一个地方，原地变成最终消息）
- 2 秒后卡片消失，但视觉上用户已经看完了
- 没有"删了重发"的突兀感

## 实现方向

- onResult → 发最终文本到同一卡片（覆盖 preview 内容，不删）
- 2 秒后 → 删卡片
- 2 秒延迟可配置
