# Cron种子文件——配置化重启恢复

> 2026-06-15 | 翀哥提出：Engine需要类似OpenClaw `cron/jobs.json`的种子文件机制

## 现状

Engine的cron系统已有持久化（`<stateDir>/cron/tasks.json`），但：
- tasks.json是运行时写的，重启时`loadTasks()`会加载
- 缺一个**手动编辑的种子文件**，类似OpenClaw的`cron/jobs.json`
- 小忆的cron需要手动写在文件里，重启自动恢复

## 现有代码结构

```
src/cron/
├── types.ts       — CronTask/CronConfig/Schedule等类型定义
├── tasks.ts       — CRUD + loadTasks/persistTasks（读写tasks.json）
├── scheduler.ts   — 调度器（tick/getDueTasks/executeTask）
├── tools.ts       — cron_create/cron_list/cron_delete工具
└── cron-plugin.ts — 生命周期（start时loadTasks+startScheduler）
```

## 方案：种子文件 `cron/seeds.json`

跟OpenClaw一样，在 `<stateDir>/cron/` 目录下放一个 `seeds.json`。

### 与tasks.json的关系

| | seeds.json | tasks.json |
|---|---|---|
| 谁写 | 人手动编辑 | Engine运行时自动写 |
| 作用 | 种子定义，重启加载 | 运行时状态（runCount/nextRunAt等） |
| 格式 | 精简（只有定义） | 完整CronTask（含运行状态） |
| 优先级 | 启动时merge进tasks | 运行时持久化 |

### seeds.json格式

```json
{
  "version": 1,
  "jobs": [
    {
      "name": "小忆内心对话",
      "enabled": true,
      "schedule": { "type": "interval", "intervalMs": 1800000 },
      "prompt": "你是小忆...",
      "delivery": { "mode": "local" },
      "notify_session": true,
      "session_message": "[inner-voice] {result}",
      "timezone": "Asia/Shanghai"
    }
  ]
}
```

### 启动时merge逻辑（cron-plugin.ts start方法里加）

```typescript
// 在 loadTasks() 之后加：
const seedsPath = path.join(storageDir, 'seeds.json')
if (fs.existsSync(seedsPath)) {
  const seeds = JSON.parse(fs.readFileSync(seedsPath, 'utf-8'))
  for (const seed of seeds.jobs) {
    if (!seed.enabled) continue
    // 按 name 去重：已存在就跳过（不覆盖运行时状态）
    const existing = listTasks().find(t => t.description === seed.name)
    if (existing) continue
    // 新建
    createTask({
      description: seed.name,
      prompt: seed.prompt,
      schedule: seed.schedule,
      delivery: seed.delivery,
      timezone: seed.timezone,
      notify_session: seed.notify_session,
      session_message: seed.session_message,
      createdBy: 'seed',
      calculateNextRun,
    })
    console.log(`[cron] Seeded task: ${seed.name}`)
  }
  await persistTasks()
}
```

**核心原则：** seeds.json只负责"确保存在"，不覆盖运行时状态。手动cron_delete一个seed任务后，下次重启会重新建回来——如果不想重建，把seeds.json里的enabled改成false。
