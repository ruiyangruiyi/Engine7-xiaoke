## 背景

前两步做完后，所有 AI 回复统一走 `cm.send` 一个出口。第三步在这个出口做敏感词拦截。

---

## 方案

### 1. 拦截位置：`channelManager.send`（manager.ts 入口）

不在 onResult 里拦，不在 preview 里拦——**在 cm.send 底层入口统一拦**。

原因：第一步让所有回复都走 cm.send 了，这是唯一出口。出口拦 = 一个口子堵一次。

### 2. 拦截条件：只拦群聊

```ts
const isGroup = inbound.channelType === 'group'
```

- 群聊 → 检查敏感词
- DM → 不拦
- 不能用 channelId 判断（微信 DM 也带 channel_id 会误判）
- 用 `channelType === 'group'` 判断

### 3. 命中行为：reject + 提示

拦截后：
- 不发原文
- 只发 `⚠️ 已拦截发送`
- 不暴露具体敏感词
- 不教绕过方式
- 打日志（console.warn 带命中的词 + 目标频道）

### 4. 敏感词来源

```
config.channels[source].sensitiveWords  →  fallback  →  config.channels.group.sensitiveWords
```

- 启动时加载到内存（Set），O(1) 查找
- 不每条消息读文件

### 5. 覆盖范围

cm.send 出口覆盖所有 AI 发出的群聊消息：
- msg_send 主动发 ✅
- session 自动回复 ✅（第一步保证走 cm.send）
- onResult 最终回复 ✅

不叠多层，不分散拦。

---

## 不拦的出口

- DM（飞书/Discord/微信 DM）
- preview 中间态（第二步已关）
- tool call / tool result / thinking 显示
- 错误消息
