### memory.db reindex 根因
**现象：** 姐姐每次 search 后 memory.db 从 3.83 GB 缩到 1.5 GB，大量历史 session 数据丢。

**调查过程：**
1. ❌ 假设：`listSessionFilesForAgent` 不扫 archive → 加扫描代码 → 还是丢
2. ❌ 假设：dist 没编译 src 改动 → 验证 dist 有 archive 代码 → 还是丢
3. ✅ 真正发现：`SESSION_SYNC_LIMIT = 500` — reindex 只处理前 500 个 session 文件。姐姐 archive 9289 个 + active 几百个，远超 500。每次 reindex 只保留前 500 个的数据。
4. src 改了 `SESSION_SYNC_LIMIT = 50000`，但还没验证（香港期间姐姐用 no-op hotfix 保命，不 reindex）

**短期方案：** dist 里 `runSafeReindex` 直接 return，不跑 reindex。代价：新 session 数据不进索引（incremental sync 应该负责，但要查为什么 incremental 不扫 archive）。

**回北京要做的：**
- 验证 SESSION_SYNC_LIMIT 改大是否真的解决问题
- 查 incremental sync（`syncSessionFiles`）为什么扫不到 archive
- 查 search 时为什么触发 reindex（正常不应该触发，只有配置变更才触发）
- 考虑改成流式处理 + 分批 commit，去掉硬编码 limit
- hotfix 持久化到 git（现在只在 dist + src，rebuild 会冲突）
