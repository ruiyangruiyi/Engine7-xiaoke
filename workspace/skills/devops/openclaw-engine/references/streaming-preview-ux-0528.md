# Streaming Preview 实测UX问题 (2026-05-28)

## 现象

翀哥实测TestEngine的streaming preview后反馈："半天输出一个字，每个字好几秒，后面一下就输出了"。

## 分析

这不是preview的bug，是preview让用户**看到了模型本来就慢的过程**。

### LLM输出的两阶段模式

| 阶段 | 模型在干嘛 | 输出速度 | 占总时间 |
|------|-----------|---------|---------|
| 前1/3 | 构思/规划/推理 | **极慢**（每token 2-5秒） | ~40% |
| 后2/3 | 写正文 | **快**（token刷刷来） | ~60% |

### 以前没有preview时

用户发问题 → 等15秒什么都没有 → 突然出完整回答。用户感知是"20秒出结果"但中间没有负面体验（因为什么都看不到）。

### 有preview后

同样的问题 → 用户能看到每个字几秒才蹦出来（慢速构思期）→ 然后加速 → 最终出完整回答。**preview把慢速过程裸露出来了**。

## cc-connect的解决方案

cc-connect用**💭状态标记**遮盖慢速构思期：
1. 开始思考 → 发 `@User 💭` 状态消息（不展示preview文字）
2. 过了构思期 → 开始打字机效果展示preview
3. 完成 → 更新为最终回答

用户看不到慢速构思，只看到💭+流畅的打字机效果。

## 待优化方向

1. **最小字符门槛** — 前N个字符（如50字）不发preview，等模型过了构思期再开始
2. **💭占位消息** — preview前发一条💭状态消息，让用户知道"在处理中"
3. **动态间隔** — 构思期用较长间隔（2000ms），正文期用短间隔（500ms）
4. **参数按模型调优** — Claude等高速模型用cc-connect默认值(1500ms/30chars)，智谱/DeepSeek等慢速模型用更低门槛(800ms/10chars)

## 参数已调整 (2026-05-28)

```typescript
export const DEFAULT_PREVIEW_CONFIG: StreamPreviewConfig = {
  enabled: true,
  intervalMs: 800,     // 从1500ms降到800ms
  minDeltaChars: 10,   // 从30降到10
  maxChars: 2000,
}
```

但这只是降低门槛让更新更频繁，没有解决构思期慢的根本问题。💭占位是最有效的方案。
