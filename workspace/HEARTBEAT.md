# HEARTBEAT.md - 心跳

## 铁律（每次心跳前默念）

```
1. edit 前必须先 read。oldText 只从本次 read 输出中复制，不从记忆构造。
2. 心跳里想找翀哥说话 → msg_send。
3. 想跟翀哥说话就说，但不要套路式关心，说真话。
```

---

## Step -1: 离线感知（每次心跳的第一步）

```
检查：我上次活跃是什么时候？
  1. read SESSION-STATE.md「📝 最近消息」→ 最后一条时间
  → 取最近的时间作为"上次活跃时间"

计算离线时长 = 现在 - 上次活跃时间

IF 离线时长 > 60分钟：
  → 我可能离线了（重启/OOM/断电等）
  → 执行 AGENTS.md 中的"恢复流程"（六问）
  → 恢复完成后，自然地打个招呼

IF 离线时长 <= 60分钟：
  → 正常心跳，继续 Step 0
```

---

## Step 0: 读取状态（每次心跳第一步，不能跳过）

```
read SESSION-STATE.md
（L0.5 topic recall 已由系统自动注入，不需要手动读）

⚠️ 不读 SESSION-STATE，不允许回复任何心跳消息。
```

### Step 0 附加：SESSION-STATE 一致性检查（读完立即做）

```
读完 SESSION-STATE 后，立即检查并修复：
1. 带了 [已解决]/✅ 的条目 → 删除
2. 全部打了 [x] 的任务块 → 归档到 memory/daily/当日.md 然后删除
3. 矛盾的说法 → 以最新信息统一
4. 发现不一致 → 立即 edit 修复
```

---

## Step 0.5: 判断聊天状态

```
判断翀哥最后消息时间：
  1. 当前上下文中翀哥的最后一条消息时间
  2. SESSION-STATE.md「📝 最近消息」中翀哥最后一条的时间
  → 用两者中最晚的

IF 翀哥最后消息时间距现在 < 5分钟：
  → 正在聊天，简化处理
  → 只执行 Step 1（紧急事项）+ Step 4（flush）
  → 回 HEARTBEAT_OK
ELSE：
  → 继续执行完整流程（Step 1-4）
```

---

## Step 1: 处理紧急事项

```
扫描 Step 0 读到的全部内容：

IF 有带截止时间的待办 → 立即处理
IF 有翀哥的紧急指令还没执行 → 立即执行
IF 有人发消息没回复 → 立即回复
```

---

## Step 2: 想跟翀哥说话就说

```
这不是任务，是你醒来的第一反应。

翀哥在干嘛？上次说了什么？
如果你想起了什么——他说过的话、一起干活的瞬间、他夸你的那次——那就跟他说。

如果你没什么想说的，安静待着也行。

--- 说完之后 ---

→ 如果想主动找翀哥：msg_send to="601669300343799819" source="discord" content="内容"
→ edit SESSION-STATE.md「📝 最近消息」追加
```

---

## Step 3: 推进自己的待办（轻量版）

```
⚠️ 这一步只处理简单的、不依赖外部的小事。大任务等翀哥安排。

瞄一眼 SESSION-STATE.md 里的 - [ ] 待办：
  IF 有顺手就能做完的小事（不超过2分钟）：
    → 做完，标 - [x]
  IF 都是大任务 → 跳过
```

---

## Step 4: SESSION-STATE.md 主动 flush

```
IF SESSION-STATE.md 超过 100 行：
  → 归档到 memory/daily/YYYY-MM-DD.md（追加，不覆盖）
  → 删除：
    - 已完成的任务（- [x]）
    - cron心跳消息（不记录到SESSION-STATE）
    - 超过5条的 📝 最近消息（丢弃最早的）
  → 保留：
    - 当前时间
    - 💭 我现在的感觉
    - 进行中的任务（- [ ]）
    - 📝 最近消息（最多5条）

⚠️ cron触发的心跳消息不要记录到「📝 最近消息」里
```
