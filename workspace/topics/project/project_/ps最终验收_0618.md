## 仍未解决的真根因（延后处理）

- CC 的 drainCommandQueue：abort → 外层 dequeue 立即发起独立新 query
- 我们的 submitMessage('next')：abort → return → 排队等当前 query 跑完
- 区别：**CC 是独立 query，我们不是**

**修复方向**（等以后 GLM 限流好或换 primary 模型再启用）：
- 选项 A：return 后强制 abort 当前 retry 循环让出 query 槽位
- 选项 B：把 submitMessage 改成"立即发起独立新 query"（不是排队）
- 选项 C：参考 cc-connect 方式——直接 Send 追加 prompt（不调 abort），不引入独立 query 复杂度
