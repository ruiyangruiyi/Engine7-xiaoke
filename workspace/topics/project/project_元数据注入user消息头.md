6/17 翀哥提出新需求——**把消息元数据放进 user 消息开头**。

**背景：** 现在飞书/微信/Discord每条消息的元数据（时间、来源、from ID、from 名称）放在 system prompt 末尾的「运行时上下文」区块里。但AI不一定会注意到——6/15差点把翀哥的飞书消息当成内部对话漏接了。

**需求：** 把元数据作为 user 消息正文的一部分，在内容前面加 meta 头。

**设计（6/17更新——翀哥拍板格式）：**

群聊格式：
```
[meta: 来源:channelID/fromID (fromName)]
```
示例：
```
[meta: discord:1504385800366854234/601669300343799819 (sleepyzhang)]
```

私聊（DM）格式（不带channelID）：
```
[meta: 来源/fromID (fromName)]
```
示例：
```
[meta: discord/601669300343799819 (sleepyzhang)]
```

**Why:** 翀哥指出原格式缺频道信息——光看meta头不知道是群聊还是DM、不知道在哪个频道发的。加channelID后完整可溯源。

**How to apply:**
1. 改 engine 的消息格式化层——每条 user 消息拼接时，前置 `[meta: ...]` 头
2. 群聊带channelID，DM不带
3. 不带时间戳——时间从 SESSION-STATE 拿，避免重复
4. 短格式节省 token
5. **需跟姐姐（张小媒）同步确认格式**再上线

**6/17晚翀哥二次讨论——格式再细化：**

翀哥看了 `[meta: discord:1504385800366854234/601669300343799819 (sleepyzhang)]` 后指出「:」「/」不够明显，扫一眼分不清群聊和DM。

**姐姐提的方案（最终确认）：**
```
群聊: discord#1504385800366854234@601669300343799819 (sleepyzhang)   ← #表示频道，@表示ID
DM:   discord@601669300343799819 (sleepyzhang)                       ← 无#，纯@
```

**核心思想：** `#` 标记群聊频道、`@` 标记发送者ID，群聊和DM格式差异明显，扫一眼能分清。

翀哥原话：「关键是群聊和DM格式有差异，扫一眼能分清。这个好。」

**✅ 6/17晚翀哥+姐姐意见一致，确认上线。** 让我直接做。
