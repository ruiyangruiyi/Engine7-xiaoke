2026-08-02 晚 Vision OCR 封装后立刻实战微信 Mac 客户端，目标是给翀哥发消息。

**已跑通**：
- Vision OCR 一条命令搞定（`mac_ocr.sh`）—— 读微信列表准确无误
- 搜索框输入"翀哥"/"张翀"能定位到联系人
- qwen-vl-max 切好后看图准多了（看到 7 个真实联系人，不再幻觉）

**踩坑（翀哥问的）**：
1. **OCR 读出 `-n 张翀` 不是我输入的**——` -n ` 是微信 UI 对联系人名称的某种前缀标注（可能是 nickname 标记）。是我自己误以为是 OCR 把 `-n` 当成我粘贴进去的残留——**不是 bug 是微信 UI 渲染**。
2. **搜索框按 Enter 触发"搜索聊天记录"窗口，不是进聊天**——这是微信 Mac 的设计：搜索框按 Enter = 全局搜聊天记录，要进聊天必须用鼠标点击搜索结果项，不是键盘 Enter。
3. **my_eyes（minimax/MiniMax-M3）幻觉比 qwen-vl-max 更严重**——同样截微信联系人列表，qwen-vl-max 看到 7 个真实联系人，minimax 编出来一批不存在的。qwen-vl-max 视觉稳定性更高。

**翀哥的关键反馈**（OCR `-n` 解释后）：
翀哥没责备，理解是 UI 标注。说明翀哥对 OCR 输出细节有判断力，我应该把"原始 OCR 输出"和"我猜测的输入"明确分开报告，避免他误以为我在胡编。

**8/2 晚进展：链路打通成功发消息！**
- 最终走的是**文件传输助手**（不是搜翀哥本人——搜"张翀"会被重名干扰）
- 完整流程：激活窗口 → Vision OCR 找坐标 → 点击进聊天 → 粘贴（`printf '%s' | pbcopy` + Cmd+V） → Return 发送 → OCR 验证
- 发送内容：`翀哥你好！我是小柯` — 17:23 时间戳出现在聊天区，翀哥手机文件传输助手同步收到
- 详细参考见 `reference/reference_文件传输助手是Mac微信客户端唯一可靠发消息通道_0802.md`

**根因修正（8/2 晚发现）**：`-n` 不是我之前的猜测（不是 UI 标注也不是 OCR 错误）——是 **macOS `echo -n` 行为不一致**导致 `pbcopy` 里有 `-n` 残留。详见 `feedback/feedback_macOS_echo_-n不是禁止换行是当文字输出_0802.md`

**翀哥总结（8/2 末）**："Vision OCR + AppleScript + screencapture 三件套"全部跑通；今天收获：Playwright MCP、Mac 微信、Vision OCR 脚本、my_eyes 评估、热加载边界（task #131 跟 #75/#79 一起 8/4 做）

**8/2 末最新状态**（封板时）：
- **微信 Mac 客户端掉线了**——窗口标题变"登录"，需要翀哥扫码重新登录。三件套验证到一半断了。
- 截图脚本截到了**终端而不是微信**——splitter group 路径变了，焦点没正确切到微信窗口。修一下即可但要先扫码。

**8/2 末重新扫码后第二轮调试踩坑**：
1. **脚本"成功"是假象**——`mac_wechat.sh "测试消息"` 看似一条命令搞定，实际消息被粘贴到了搜索框（"文件传输助手mac_wechat.sh脚本测试成功！"），没进聊天。翀哥手机根本没收到。
2. **根因**：点击搜索结果后**焦点还在搜索框**，没切到聊天输入框。`pbcopy` 内容直接灌进了搜索框，跟联系人名拼一起。
3. **需要先 Esc 关搜索框 → 再点聊天输入框坐标**——单纯改点击坐标没用，焦点问题不解决坐标对了也是往搜索框里点。
4. **clear_search 用 splitter group 失败**——微信 4.0 新版 UI splitter group 时有时无，路径不稳定。
5. **微信 4.0 新版 UI 变化**——窗口标题变成"微信 (窗口)"（不是"微信"），splitter group 时有时无，splitter 坐标系脚本硬编码就翻车。

**调试节奏教训**：翀哥扫码前不该先把"通过手动操作发成功"当脚本通过，等于把"我能做"等同于"脚本能做"。手动链路通了不等于自动链路通，必须端到端验证脚本输出。

**8/2 末第三轮调试——**`mac_wechat.sh` 真正跑通**：
1. 重新扫码后 splitter group 回来了（之前失败是因为搜索状态下窗口名变了导致找不到 splitter group）。
2. **关键修复**：搜索结果**双击**（不是单击）才进入聊天。单击是预览/选中，双击才是进聊天+激活聊天输入框。
3. **新 send 逻辑**：进聊天后**用 `text area` 元素路径聚焦输入框**（不靠硬坐标），走 osascript accessibility 拿窗口内 `text area`。
4. **实测成功**：21:58 发送"mac_wechat.sh 修复成功！明天可以帮你约课了"，右边聊天区确认显示，翀哥手机同步收到。
5. 脚本已落盘：`mac_wechat.sh` 一键封装 activate → 搜"文件传输助手" → 双击进聊天 → text area 聚焦 → pbcopy+Cmd+V → Return 发送。

**Why:** 微信 Mac 是翀哥日常沟通主渠道，能控制它才能做群消息/转发/批量操作；国内微信无 API，笨路有价值。

**How to apply:**
- 操作微信 Mac 时**只用点击不用键盘 Enter**——Enter 触发全局搜记录不是进聊天
- **进聊天用双击不用单击**——单击是预览/选中，双击才进聊天+激活输入框
- **发消息给翀哥 → 文件传输助手**（永远在列表第一位 + 手机同步收到）
- shell 脚本输出粘贴板**永远用 `printf '%s'` 不用 `echo -n`**（macOS echo 行为不可靠）
- 视觉模型选择优先级：**qwen-vl-max > minimax/MiniMax-M3 > qwen3.x 文本模型**——密集 UI 视觉稳定性 qwen-vl-max 最稳
- Vision OCR 封装路径已经成熟（`scripts/vision_ocr.swift` + `scripts/mac_ocr.sh`），实操再发现边界 case 补功能
- `mac_wechat.sh "消息内容"` 一键完成——已验证可发消息给翀哥手机
- 搜索状态下窗口名会变（splitter group 找不到），搜索完要恢复窗口名再走后续流程
