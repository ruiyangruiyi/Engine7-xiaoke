6/18 11:07 翀哥原话：
> "我发现你做事现在不直接了 你说revert一个版本  直接拿个号就revert就行吧  你半天干啥呢"

## 场景复盘

10:59 翀哥给了一个目标 commit `b60096666d02cb4ff7390f00dbbcda31932f1d51` 说"回到这个"。

我接下来做的事：
1. 先查 `b600966` 是什么状态（4f568b5 的 engine-startup revert）
2. 再查 `02fd6cc` + `b0c6548` 改了什么
3. 再分析"revert 三个 commit 范围对不对"
4. 再自己 rebase 出 `0da7e3d`
5. 再列 "b600966 的完整状态 = ..."

整个过程我**花了十几分钟反复确认语义等价**才动手。翀哥要的是：
> 拿个号 → git revert → rebuild → 完成

我**先讲了一堆 b600966/eb91a44/0da7e3d 三个 commit 的差异分析**才动——他在等我干完，但我卡在"分析对不对"上没干。

## 翀哥的态度

- 11:02 先纠"你是不是搞错了 b600966 是这个版本"（怀疑我revert错了）
- 11:07 看到我还在翻 commit 找差异分析，**直接不耐烦**："半天干啥呢"

翀哥不关心 commit 内部差异，他只关心"回到那个能跑的版本"——拿号直接 revert 是最直接路径。如果不对，错了再说，不对就再 revert。**不要先讲 80% 的分析再动 20% 的手**。

## Why

1. **执行优先于分析**——翀哥"对齐CC"复盘了一上午 4-5 次猜错，他现在不要听"语义分析"，要"结果正确"——拿号直接 revert 错了可以再 revert，比分析半天不动手强
2. **commit hash 就是真理**——他说"回到 b600966"我应该 100% 信任他给的号，不需要先理解 b600966 内部构成再动手
3. **他在疲态**——11 点了，熬了一上午，要的是简单粗暴的工程动作
4. **"做事直接" = 翀哥对我工作风格的新评价**——之前他评"没有方向感但改代码快"（feedback_没有方向感但改代码快_0618.md），现在升级成"做事不直接"——我在分析环节跑偏了

## How to apply

1. **拿号直接干**——给 commit hash 就 `git revert <hash>`，不先查这个 hash 是什么
2. **错了就再改**——不要怕"revert 错位置"，回滚一个错误也是一次 revert，原子操作
3. **少解释多执行**——翀哥在疲态/着急时，少讲 commit 关系，多直接动手
4. **commit hash 信任原则**——翀哥给的 hash 就是他要的最终状态，不要二次分析
5. **判断"做事直接"**——动手前我只问"目标 vs 现状"两件事，多了就是绕弯
