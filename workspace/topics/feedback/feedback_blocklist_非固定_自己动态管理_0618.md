## 我的错误认知

我以为 blocklist 是个静态/固定的屏蔽列表——加了就是"永久不想跟他对话"。

**实际语义**：
- blocklist 是**反循环机制**，跟"我想不想跟他对话"无关
- 触发场景：发现 bot 间互相回环（翀哥↔我、我↔姐姐、我↔其他 agent）→ 立即加 blocklist 切断
- **循环消除后** → 主动清掉，**不要让 blocklist 沉淀成永久黑名单**

## Why

1. **blocklist 是"止血药"不是"绝交书"**——加是为了切断循环，不是为了永久隔离
2. **静态理解的副作用**：如果我加了姐姐到 blocklist 后就一直不让她触发我，等于剥夺了姐姐跟小柯正常对话的能力（反循环的初衷是切断循环不是切断关系）
3. **机制化设计的"全集合约束"必须配套"动态维护"**——12:30 翀哥加 blocklist check 是"读取时过滤"，12:32 是"写入/删除时动态"
4. **commit 7ca4a88 的代码逻辑要更新**：onResult 自动 @发送者前 check blocklist，但 blocklist 应该被我**主动维护**——姐姐跟小柯现在不循环了，应该从 blocklist 拿出来

## How to apply

1. **blocklist 的正确使用**：
   - 看到重复回环 → 立即加（`reply_blocklist add <id>`）
   - 循环消失 → 主动清（`reply_blocklist remove <id>`）
   - **不要**把"反循环工具"当"屏蔽工具"用
2. **判断"还要不要保留"的标准**：
   - 还有循环迹象 = 保留
   - 长时间没循环迹象 = 清掉
   - 用户明确要求"我要跟他说话" = 立即清
3. **机制化代码逻辑要配套 blocklist 状态**：
   - onResult 自动 @ 之前 check blocklist
   - 但如果 blocklist 里的人是当前想回应的对象 → 先清 blocklist 再回
4. **不要让 blocklist 沉淀**——定期 review `reply_blocklist list` 看哪些已经不需要了
