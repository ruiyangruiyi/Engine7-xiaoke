# 7/15 翀哥批评：甩锅/改通用代码/revert不验证/不踏实

## 事件
7/15 Perception 模块开发 + ICE排查，翀哥批评5个问题。

## 翀哥批评要点

### 1. 甩锅——直接去修，不要证明不是自己的锅
- 翀哥说 block 有问题，我一直证明"不是我的锅"
- **教训**：翀哥说有问题就去看去修，不是在事实层面争论对错

### 2. 改了通用代码
- 为 perception block 改 message-dispatcher.ts
- **教训**：不要为局部需求动通用代码，感知数据走独立 block 就够了

### 3. 效率低——前半段等确认不自主执行
- 前半段等翀哥确认才开工
- **教训**：自主推进，不需要确认的事直接做（与7/12同一教训，又犯了）

### 4. revert 后不验证
- 恢复旧版感知格式后，没有验证能不能跑
- **教训**：任何 revert 都要验证，不改代码不等于一定能跑

### 5. 不踏实——跑了很久的代码不要随便动
- 动了稳定运行很久的通用代码
- **教训**：稳定代码除非必要不碰，跑了很久的代码有隐性依赖

## 与7/12教训的关系
- **甩锅** = 出问题先查自己（7/12）的延伸——不仅git diff查自己，翀哥指出的问题直接修
- **等确认** = 7/12同一问题又犯，自主执行原则没有内化
- **不改通用代码** = 新教训
- **revert后验证** = 新教训
- **不踏实** = 新教训

## 正确做法
1. 翀哥指问题 → 直接去修，不争论谁对谁错
2. 局部需求不动通用代码
3. 自主推进不等确认
4. 任何修改（包括revert）都要验证
5. 稳定代码不碰
