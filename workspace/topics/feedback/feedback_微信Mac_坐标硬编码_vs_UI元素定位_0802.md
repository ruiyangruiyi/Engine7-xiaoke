2026-08-02 末微信 Mac 脚本第二轮调试踩坑总结——手动操作成功不等于脚本能跑，硬编码坐标是死路。

**两个关键发现**：
1. **手动链路通 ≠ 自动链路通**——之前手动点 `text area` 路径成功发消息，误以为脚本通过。实际脚本走的是"点击搜索结果坐标"，**焦点还在搜索框**没切到聊天输入框，`pbcopy` 内容直接灌进了搜索框跟联系人名拼一起。
2. **微信 4.0 新版 UI splitter group 时有时无**——窗口标题变"微信 (窗口)"，splitter 坐标系脚本硬编码就翻车（截到终端不是微信）。

**第三轮调试新增发现**（8/2 末真打通）：
1. **进聊天必须双击**——单击搜索结果是预览/选中，双击才是进聊天+激活聊天输入框。手动用单击也能进是巧合，脚本必须双击。
2. **send 路径走 text area 元素而不是坐标**——osascript 拿窗口内 `text area` 元素聚焦输入框，避免所有硬编码坐标。
3. **搜索状态下窗口名会变**——splitter group 找不到是因为搜索状态切换了窗口名，搜完要恢复窗口名再走后续逻辑。

**Why:** 微信 4.0 新版 UI 不稳定，硬编码坐标链路脆到不能复用。手动操作能成是因为走了 UI 元素路径（系统自动找到 `text area` 元素），脚本走坐标点的是搜索框不是输入框。

**How to apply:**
- 操作微信 Mac 客户端**走 UI 元素定位**（osascript 通过 accessibility / "text area" 路径）而不是坐标硬编码
- **搜索框是嵌套结构**——`text field 1 of text field 1`（不是单层 `text field 1`）
- **搜到联系人后必须关搜索面板**（Cmd+W 或 ESC），不然会残留上次搜索内容，粘贴新内容会拼成 "上次搜索词+本次搜索词"
- **进聊天用双击**（不是单击，单击只是预览）——但**关掉搜索面板后单击列表项也能进**（群聊走这条路径）
- 搜到联系人 → **走 text area 元素路径聚焦输入框**（不靠硬坐标）
- `clear_search` 不能依赖 splitter group——微信新版 splitter 不稳定，要找其他路径
- 调试脚本必须端到端看实际产出（消息是否进聊天区），不能信"脚本没报错 = 成功"
- **先用手动操作走通的路径**反过来给脚本用，比从坐标硬编码开始写更稳
- **群聊 vs 单聊流程不同**：
  - 单聊（文件传输助手）：在列表第一行，直接双击进 → text area 聚焦 → 粘贴发送
  - 群聊：必须**搜索 → 关搜索面板 → 群浮到列表顶部 → 单击列表项**进聊天，双击反而容易切错
