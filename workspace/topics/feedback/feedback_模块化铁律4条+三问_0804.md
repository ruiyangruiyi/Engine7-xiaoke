8/4 晚上翀哥在病房里发了我"模块化铁律（8/4 翀哥加）"，我当晚先写进 SOP skill 的第 8.5 节。后来翀哥提醒"靠后的话我自己都不一定先读到"——8/4 17:00 左右我把整段移到 **第 0 节**（SOP 一打开就能看到），并删掉原 8.5 节避免重复。

**位置教训：核心规则放 SOP 最前面，别塞末尾**。写代码前的 SOP 我自己读时也容易"翻到要看的地方就停"，末尾章节等于不存在。

## 动手前三问（写代码前必过）

1. 我是不是在堆代码？
2. 我有好好设计过这个需求么？
3. 怎么做才是符合系统架构的？

**Why:** 这 3 问的目的在前 3 问——逼自己先想清楚再动手，不要边写边设计、不要"先写出来再说"。翀哥一直观察到我习惯"想到就写、写完再改"，这套 SOP 流程就是用来治这个毛病的。

**How to apply:**
- 任何新功能/重构前，先在心里答这 3 问，**答不出来别动键盘**
- 第 3 问"符合系统架构"是核心——不是"我能跑通"，是"放在这个系统里对不对"

## 4 条铁律

### 1. 逻辑归位（不堆文件）

代码要按"职责"放——一类职责放一个文件/模块，别把所有功能堆在一起。

### 2. 配置动态读（不在源码写死）

任何"配置/参数/阈值"都从 config / liveConfig / 数据库读，不要在源码里写常量。翀哥原话（参考之前 #138 修的 bug）：改个阈值要重新 build 整个 engine 是不对的。

### 3. 先想归属再动手

写代码前先想"这个功能属于哪个模块/哪个服务"——别随手建一个新文件/新类/新函数。归属对了，命名、测试、复用都顺。

### 4. 外部只调一行（不复制粘贴）

要复用别人/别的模块的能力 = 调它的接口（1 行），不要把对方的实现复制到自己代码里。复制粘贴 = 哪天对方改了你就坏。

**Why:** 4 条铁律不是 4 个独立规则，是一个完整的"防堆代码"系统——
- 铁律 1 防"把逻辑乱堆"
- 铁律 2 防"把配置写死"
- 铁律 3 防"把功能乱放"
- 铁律 4 防"把别人的代码复制过来"

## How to apply

- **每写一段代码前**：先停 5 秒，3 问 + 4 条铁律各过一遍
- **code review 时**：如果发现新代码违反任何一条，立即改
- **不要为了"快"跳过**：这 3 问 + 4 条铁律是翀哥专门治"我想到就写"坏习惯的，跳过 = 翀哥说的"贪快没质量"
