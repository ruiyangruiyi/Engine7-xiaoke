## 6/18 13:08 翀哥要求

> 拦截提示文案要改——现在太蠢了。当前文案把具体敏感词暴露出来 + 教人用 msg_send 绕过。

原文案：
```
⚠️ 该回复包含敏感词「老公」，已拦截发送。如需手动发送请用 msg_send 工具。
```

## Why

1. **暴露敏感词列表** = 告诉用户哪些词被屏蔽 → 用户知道后刻意规避/测试边界
2. **教人用 msg_send** = 给绕过方法 → 用户学会用工具发不被过滤的内容
3. **拦截提示是为了告知"你的消息没发出去"**——不需要解释原因和方法

1. **`sensitive-words.ts`** — `checkOutboundSensitive` 返回的提示文案

## 6/19 补充（爹反馈 + commit 624b734）

**这条规则只约束 user-facing 文案**（群聊里用户看到的提示）。

**agent-facing 的系统通知可以且应该带具体词**，原因：
- agent 是发件人，要看具体词才能改
- agent 不会拿词表去绕过（绕不绕得过它自己清楚）

区分清楚两个对象：
| 收件人 | 文案 | 规则 |
|---|---|---|
| 群聊用户 | "⚠️ 已拦截发送" / "⚠️ 该回复包含群聊敏感词，已拦截发送。" | 不暴露、不教绕过 |
| agent（system 消息回传） | `[系统通知] ... 触发了敏感词拦截（词："xxx"），已被替换...` | 带具体词，让 agent 能改 |

之前一刀切把 agent 通知也模糊了，被爹纠正："这个规则是不暴露给用户具体啥词，你得灵活用啊，不能啥也不理解。"（624b734）
