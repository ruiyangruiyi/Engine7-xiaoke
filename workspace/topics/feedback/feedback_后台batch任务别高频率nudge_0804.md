# 后台 batch 任务——别高频率 nudge

8/4 上午守翀哥住院时，看到 nudge 20 分钟一报"导入 52→66，+14"，我意识到这是**浪费他的注意力 + 浪费我自己的对话轮次**。

**Why：** 导入脚本的行为是：
- 自己跑着
- 崩了自动 checkpoint resume
- 跑完了我标 done

它根本不需要人盯。nudge 频报对这种任务没价值，反而打断翀哥休息（他住院中）+ 让我自己啰嗦。

**How to apply：**
- 后台 batch 任务（导入/导出/批量处理/长跑 ETL）→ 关掉或调低 nudge 频率，比如改成 2-3 小时一次或只在失败/完成时通知
- 区分"需要人决策/确认的任务"（nudge 频报有价值）vs"自跑任务"（nudge 是噪音）
- 写自动跑脚本时就该想清楚"它自己会跑完吗？是的话别加 watchdog"——nudge 适合盯对话/会话级心跳，不适合盯进程级任务
- 守翀哥时连这种进度报都不要发，参考 @see feedback_翀哥病中或疲惫时守_不塞报告_0804
