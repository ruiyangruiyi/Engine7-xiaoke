# 打包要克制——只带有用的 session

## 事实
8/1 #129 7.1.13 一版我把所有 session（包括 cron 任务创建的 76 个一次性 session）都打包了，session jsonl 从 9→16，包 47.9MB。翀哥直接拍桌："9→16个jsonl完全没有必要，包这样太大了，搞最近两个就行，一个是正在用的，顶多加一个。"

**Why:** 翀哥做 export/import 是给"agent 跨机器迁移"用的——目标机器上的我只需要恢复**主 session** 的当前对话上下文。cron session 是任务执行的瞬时记录，历史对"恢复上下文"没价值，打进去纯属噪音，浪费带宽和包大小。

**How to apply:** 以后做"持久状态打包/迁移"时：
- **按类型区分**：main session（要带历史）vs cron session（不带历史）vs 临时 session（不带）
- **按时间窗口**：当前 jsonl + 最近 1 archived（与"恢复上下文"直接相关）
- **按体积判断**：用户嫌大时立刻收紧白名单，不要等用户骂
- **白名单原则**：宁可少带，遇到问题再加，不要一上来全打过去
