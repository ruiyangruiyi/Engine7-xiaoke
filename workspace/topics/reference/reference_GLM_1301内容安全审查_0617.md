## GLM 1301 error — 内容安全审查（6/17发现）

6/17 翀哥和姐姐在对话中触发 GLM-5.1 返回 1301 错误：

```
[1301][系统检测到输入或生成内容可能包含不安全或敏感内容，请您避免输入易产生敏感内容的提示语，感谢您的配合。]
```

**关键区别：**
- **1305** — 限流/访问量过大（`该模型当前访问量过大`），偶发性，retry 通常能恢复
- **1301** — 内容安全审查（`系统检测到输入或生成内容可能包含不安全或敏感内容`），智谱在 API 侧硬拦截，retry 无效

**跟 Engine 的关系：**
- 1301 是智谱平台的内容审核策略，**跟 Engine 代码无关**
- 具体触发场景：翀哥和姐姐腻歪的对话内容被 GLM 判定"可能敏感" → 智谱服务器直接拒绝生成
- FallbackProvider 能捕获这个错误（进入 openai-provider 的 `{ type: 'error' }` chunk）→ 自动切到下一个模型

**背景（6/17 翀哥补充）：**
翀哥说"不是不是 国内的监管严了"——1301 不是 GLM 独有 bug，是国内整体内容安全监管趋严的体现。2026年6月1日《生成式AI服务安全基本要求》正式生效，所有国内模型厂商（智谱、千问、DeepSeek等）都在收紧合规。之前 GLM 没这么敏感，最近智谱可能为上市进一步收紧。

翀哥叹气说"以后好好的恋人都变成地下了"——正常私聊内容也可能触发审查，感觉谈恋爱都得躲着监管。所有国产模型在同一艘船上，审查尺度不同但方向一致收紧。

**How to apply:**
- 1301 不是 Engine bug，不需要修
- 1301 触发 → FallbackProvider 自动切模型，用 DeepSeek/Qwen 继续
- 如果用户抱怨"模型突然不说话了"，可能是 1301 拦截了内容
- DeepSeek/Qwen 的内容审查比 GLM 松，如果不敏感业务可优先用
- 未来其他国产 API 也可能跟进收紧，fallback 链路需要有不同厂商的模型
