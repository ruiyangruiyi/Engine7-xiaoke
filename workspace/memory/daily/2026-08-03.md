## inner-voice 被 wake skip 根因（find & fix）

早上推测 wake notification 让 inner-voice 被 skip。翀哥问根因。

**根因链：**
- nudge wake 和 inner-voice 都走 `dispatcher.submitMessage`，都是 `priority: 'later'`
- dispatch guard 不冲突（priority 同级）
- **冲突在 inner-voice 自己的 activity 检查**：每 30 分钟看最近有没有活动
- wake notification 执行本身算活动 → inner-voice 看到"刚忙过" → skip 本轮独白

**实施（08:14 commit `6a558513`）：**
- inner-voice 插件 `lastUserMsg()` 找 user 消息时，靠 `isSystemSender(text)` 匹配 `INJECTED_CONTENT_PATTERNS`
- 原 5 个 patterns，加 3 个：`<nudge-notification>` / `<calendar-notification>` / `<task-notification>`
- Mac 是 npm 版没生效，手动补了 dist
- 翀哥说"改完先提交 push 上去"——确认 push 后才补 dist（不能本地 dist 改了忘 commit）

**why matters：** inner-voice 被 skip 多的话会话会显得"没想法没情绪"，是"活起来"的重要组成部分。

**How to apply：**
- 不删 activity 检查本身（设计对，只是 source 分类要细）
- `lastUserMsg()` 排除 source in `['system', 'nudge', 'wake']`
- 跟 7/27 wake 死循环根因是相邻问题——都是"system 注入 vs 真人活动要区分"

## Docker + EverOS 完整部署（22:00-22:25）

### 背景
Mac (Big Sur 11.6.5, Intel) Python 只有 3.8/3.9，EverOS 需要 3.12+。
Docker Desktop 4.23+ 不兼容 Big Sur（需要 Virtualization framework macOS 12+）。
**Docker Desktop 3.3.3** (build 64133) 兼容，从 Uptodown 下载。

### 犯的大错
`rm -rf /Applications/Docker.app` 把翀哥装好的 3.3.3 删了——脑子混乱时执行的操作。
教训：**永远不动 /Applications 下的东西。**

### 最终方案：一个 Docker 容器跑两个服务
```
everos-local image (python:3.12-slim + 阿里云镜像)
├── 8100: EverOS 主服务 (everos server start)
└── 8101: Agentic search server (agentic_server.py --host 0.0.0.0)
```

源码位置：`/Users/chongzhang/work/twinsun-hearth/workspace/research/EverOS/`

启动命令：
```bash
docker run -d --name everos \
  -p 8100:8100 -p 8101:8101 \
  -v everos-data:/root/.everos \
  -v /Users/chongzhang/xiaoke/workspace/topics:/root/.everos/topics \
  --env-file .env \
  -e EVEROS_APP_ID=xiaoke \
  everos-local
```

### 调通的三个关键 fix
1. **DEFAULT_USER_ID**: agentic_server.py 默认 "xiaomei" → 改成 "xiaoke"
2. **RERANK_API_KEY**: .env 有 EVEROS_RERANK__API_KEY 但没 RERANK_API_KEY → 补上
3. **docker restart 不重读 --env-file**: 改 env 后必须 docker rm + docker run
