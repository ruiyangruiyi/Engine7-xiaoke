## FlashHead 形象切换闪现修复（彻底搞定）

### 问题现象
1. 切换形象时闪现旧形象（code_girl → sister_cyber 时闪一下 code_girl）
2. ASR speech end 偶发闪现
3. 必现：说话 generate 时出来一帧旧形象，嘴型延迟几秒才正常
4. 后端重启后 settings 界面 TTS provider 不同步

### 根因分析
**三个角色共享 pipeline 状态，但只用了两把不同的锁：**

| 角色 | 操作 | 用的锁 |
|------|------|--------|
| idle worker | `_generate_idle_chunk` (line 448) | `_inference_lock` ✅ |
| speech inference | `_process_chunk` (line 262) | `_inference_lock` ✅ |
| frame_collector | 后备帧 `_idle_frame` | **不拿锁** ❌ |
| switch_avatar | `get_base_data` | `_lock_inference`（没人检查，等于没加）❌ |

**闪现路径**：switch_avatar 改了 pipeline.ref_img_latent（新形象），但 idle worker 在窗口里抢跑，读到「新 ref + 旧 latent_motion_frames」→ 产出畸形帧 → 污染 processor 缓存 → 下次 speech inference 第一帧就是旧形象。

**frame_collector 的 `_idle_frame`**：在 processor.start() 时一次性创建，切换形象后没更新 → 队列空时直接推旧形象的静态帧。

### 修复方案（3行核心代码）

**carpo_avatar_server.py — switch_avatar：**
```python
# 旧：server._lock_inference = True（没人检查）
# 新：持 idle/speech worker 同一把锁
with server.processor._inference_lock:
    get_base_data(server.pipeline, image_path, 42, False)
    server.cond_image_path = image_path
    server.processor._initial_latent_1slice = server.pipeline.ref_img_latent[:, :1].clone()
    server.processor._latent_motion_frames = server.pipeline.latent_motion_frames.clone()
    server.processor._idle_frame = server.processor._make_idle_frame(server.pipeline)  # ← 关键
```

### FlashHead pipeline 数据流速记
```
pipeline.ref_img_latent        → generate() 里作为 y 参照物（形象）
pipeline.latent_motion_frames  → generate() 里作为 noise 起点（动作）
pipeline.original_color_reference → 色调校正参照

processor 缓存：
  _initial_latent_1slice  = ref_img_latent[:, :1]
  _latent_motion_frames   = 每步推理后更新
  _idle_frame             = original_color_reference 转的 BGR 静态帧

每次推理前（idle/speech）：
  pipeline.latent_motion_frames = processor._latent_motion_frames.clone()
```
